# Jev（RLCDで訓練された新型フロンティアモデル）

> **TL;DR**: ChatGPTの共同発明者を名乗る@CompleteSkepticが、2年間ステルスで開発した新しい訓練手法「RLCD」と、それで作った新型フロンティアモデル「Jev」を2026-09-15に発表した。告知文は「20-200x faster」「40-400x」で途切れており、手法とスペックの詳細は未収集。

> 📌 X bookmark: 57,568（2026-09-19 時点）

@CompleteSkepticは発表ポストで、ChatGPTを共同発明した後「超人的なチャットモデルがなぜAGIにつながっていないのか」を問い続けてきたと書く。その答えとして示したのが、モデルを訓練する新しい方法 **RLCD** と、新しいタイプのフロンティアAIモデル **Jev** である。発表の問題設定は「チャットモデルの延長ではAGIに届かない」という前提に立っており、Jevはチャットモデルとは別系統のモデルとして位置づけられていると読める。

捕捉できた数値は「20-200x faster（20〜200倍高速）」と、比較対象が途切れた「40-400x」の2つだけである。何と比べて速いのか、RLCDが何の略か、提供形態（API・価格）はポスト本文からは読み取れない。発表には動画が添付されているが中身は未捕捉。

## ブラウザエージェントでの利用例（推論による接続）

browser-useが公開した[[tools/jev-ultrafast]]は「TypeSafe's Jev」を決定器として使い、ページの要素テーブルから操作と対象を1回のリクエストで同時に予測させている。同名で時期も近いため本ページのJevと同一と考えられるが、@CompleteSkepticのポストにはTypeSafeという社名が出てこず、同一性は未確認である。同一なら、Jevは文章を生成する代わりに「番号付きの選択肢から確率付きで選ぶ」型の出力を持ち、自由記述の生成は小型LLMに任せる使われ方をしていることになる。「20-200x faster」という主張とも、生成でなく選択に絞ることで速くするという設計とも整合する。

## 使った側の記述とオープンウェイトのクローン

mizchi は Zenn 記事で Jev を「自然言語を生成せず、用意した選択肢にスコアを付けることに特化した API」と説明し、1リクエスト500ms（日本からは遅延が乗って実質2fps）と書いている。選択型の出力という点は上の browser-use の使われ方と一致する。mizchi によると公開から数日で Jev クローンが大量に作られ、そのうち Convai Innovations の Laya（BERT 系 encoder＋decision head、322M〜421M）は手元の MLX で1判断8〜9msまで速くなった（[[tools/laya-mlx]]）。ただし賢さは Jev が上で、Jev は学習抜きに選択判断を実現している点が強みだと mizchi は見ている。

## 外部からの内部構造推測（未収集）

@iwashi86 は、Jev の内部アーキテクチャを推測した技術記事「Jev's Architecture Unmasked」のメモを投稿している。@iwashi86 のまとめによると、この記事は Jev の API を約1万回呼び出して内部構造を推測したもので、従来の言語モデルによる分類・ルーティングはトークンを1文字ずつ逐次生成するため膨大な無駄な計算コストが発生していた、という問題設定から始まる。捕捉できたメモはここで途切れており、記事が推測した構造そのものは未収集である。問題設定は、上の mizchi の「生成せず選択肢にスコアを付ける」という説明と同じ方向を指している。
