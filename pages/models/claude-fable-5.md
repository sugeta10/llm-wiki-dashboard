# Claude Fable 5 / Mythos 5

> **TL;DR**: [[companies/anthropic]] が一般公開した初の **Mythos クラス**（Opusの上位ティア）モデル。中身は Fable 5 = Mythos 5 で同一、違いはセーフガードの有無だけ。

> 📌 X bookmark: 11,120（2026-06-09 時点、@RLanceMartinによるFable 5ループ設計解説）

Mythos クラスは性能が高すぎて[[models/claude-mythos|Mythos Preview]]として一般公開を見送ってきたティア。今回はセーフガード（分類器による検知＋[[models/claude-opus-4-8|Opus 4.8]]へのフォールバック）を整備したことで、**Fable 5**を全ユーザーに開放できた。**Fable と Mythos は同一の基盤モデル**で、サイバー・生物化学・蒸留の領域でセーフガードを掛けたものが Fable、外したものが Mythos。Mythos 5 は Project Glasswing のサイバー防御パートナーと一部生物研究者にのみ提供される。名称の由来は Fable（ラテン語 *fabula*「語られるもの」）が Mythos（ギリシャ語）と同根で、両者を分けるのはセーフガードのみという設計思想を反映している。

## 検証済み事実

- 2026-06-10: **Fable 5 と Mythos 5 を同時launch**。Fable 5 は本日より全所で利用可、Mythos 5 は Glasswing パートナー（サイバーセーフガード解除）＋近日select生物研究者（生物化学セーフガード解除）に限定
- **価格: 入力 $10 / 出力 $50（per 1Mトークン）** — Mythos Preview（入力$25/出力$125）の半分以下
- API モデルID: `claude-fable-5`
- ほぼ全ベンチで state-of-the-art。タスクが長く複雑なほど他Claudeモデルに対するリードが拡大
- **ソフトウェアエンジニアリング**: Stripe が早期テストで「数ヶ月の作業を数日に圧縮」。5,000万行のRubyコードベースで、人手なら2ヶ月超かかるコードベース全体のマイグレーションを1日で実施。Cognition の FrontierCode 評価でフロンティアモデル最高（medium effortでも）。過去Claudeよりtoken効率も向上
- **知識労働**: Hebbia Finance Benchmark で全モデル中最高スコア。IMC のトレーディング分析評価をほぼ全面でクリア
- **ビジョン**: vision系SOTA。科学図表からの数値抽出、スクショのみからのWebアプリ再構築が可能。**Pokémon FireRed をvision-onlyの最小ハーネスでクリア**（過去モデルは複雑な補助ハーネスが必要だった）
- **メモリ/長文脈**: 数百万トークンにわたり集中を維持し自分のノートで出力を改善。Slay the Spire でファイルベース永続メモリの効果が Opus 4.8 の3倍、最終actへの到達も3倍
- **創薬（Mythos 5）**: 社内タンパク質設計プロセスを約10倍加速、14ターゲット中9つで有力候補。分子生物学の新規仮説をブラインド比較で科学者が約80%選好、E. coli タンパク質の新機構仮説が独立研究で裏付け
- **ゲノミクス（Mythos 5）**: 1週間超のほぼ自律作業で、138動物種・数百万細胞のデータから細胞役割同定MLモデルを設計・訓練。Science誌掲載モデルを上回り、かつ100倍小型
- **アラインメント**: Mythos 5 の誤整合行動（欺瞞・誤用への協力等）は低水準で Opus 4.8 と同程度。Fable も同一基盤モデルゆえ同様
- **データ保持ポリシー変更**: Mythos クラス（および今後の同等以上モデル）は1st/3rdパーティ全トラフィックで**30日保持を必須化**。訓練・非安全目的には使わず、人間アクセスのログ化と30日後削除を制度化

## ループ設計・メモリ能力（@RLanceMartin, Anthropicリサーチャー）

Fable 5 は自己修正ループとセッション間メモリの両面で前モデルを大きく上回る。

### 自己修正ループ（Parameter Golf ベンチマーク）

[[concepts/loop-engineering]] のループ設計で Fable 5 と Opus 4.7 を比較したAnthropicリサーチャーの実験（Claude Managed Agents + 8xH100 GPU セルフホストサンドボックス）:

- Fable 5 はトレーニングパイプラインを Opus 4.7 の **約6倍** 改善
- **アプローチの違い**: Fable 5 は構造的変更（アーキテクチャ変更）に賭け、量子化のリグレッションを乗り越えて最大の勝利を達成。Opus 4.7 は小さな勝利を出すと以降ほぼ同じテンプレート（スカラー値の調整→計測→キープ）を繰り返す
- **検証サブエージェント**: 作成者自身の自己批評より、独立したコンテキストウィンドウを持つ検証サブエージェントの方が Fable 5 では高性能。[[tools/claude-managed-agents]] の Outcomes が自動でグレーダーサブエージェントを生成するのはこれが理由

### セッション間メモリ（Continual Learning Bench 1.0）

@pgasawa らが公開した Continual Learning Bench 1.0 でのメモリ能力比較（CMA メモリ付き、同一FSを複数セッションで共有）:

| モデル | メモリ活用の段階 | 検証カバレッジ |
|--------|----------------|-------------|
| Sonnet 4.6 | ステップ1（失敗ノート+推測の羅列）で停止。事前メモを参照しない | - |
| Opus 4.7 | ステップ3（不確実性フラグ付きスキーマ参照）で停止 | 17%（7〜33%） |
| Fable 5 | ステップ5まで完走（最強実行時） | 73%（22/30） |

**失敗→調査→検証→蒸留→参照** の5段階メモリ活用プログレッション。Fable 5 は失敗から汎用ルールを導出し、後続セッションでそのルールを参照する。Sonnet/Opus は失敗ノートを蓄積するだけで蒸留・参照まで至らない。

**設計の含意**: Fable 5 は直接プロンプトして操作するより、**環境フィードバックに応じて自己修正できるループを設計する**（`/goal` や Outcomes 等）方が性能を引き出せる。

## 丸投げ自律開発の実証（水島宏太 / @kmizu）

上の「自己修正ループを設計して任せる」使い方の具体的な実証例。構文解析を専門とする水島宏太（ネクストビートのテクノロジー・エバンジェリスト、PEG研究者）が、仕様書も技術スタック指定もなく [[tools/claude-code-goal|/goal]] に「日本の教育業界がDXしないと壊れるほど素晴らしい無料教育サイトを作って。GitHub Pagesで公開、デザイン/UXも最高で」程度のゴールだけを与え、放置時間合計2時間足らずで全6コース・54レッスンの教材サイト「言語の庭」が完成したと報告している。深津貴之（[[people/fladdict]]）のポストをもじったゴール設定で、進捗ごとに相槌を打った以外は設計にも実装にもほぼ口を出していない。

指示されていないのに Fable 5 が自分で積み上げた設計判断の連鎖：

- 教材専用の日本語キーワード言語「にわ語」を自作（タートルグラフィックス・日本語エラーメッセージ・「エラーは誠実な読み手からの返事」という設計思想つき）
- 字句解析→構文解析→評価の3工程をブラウザ内の純TypeScriptで実装（バックエンドなし）。トークン列・構文木・評価値を同時表示する「MiniLangLab」、無限ループ対策の fuel 方式（実行ステップ上限）、ユーザーJSはWeb Workerに隔離してタイムアウトkill
- コース3で正規表現エンジン＋NFA可視化、コース5でチューリング機械シミュレータ、コース6で型検査器まで自前実装。停止性問題・対角線論法・チョムスキー階層まで扱う構成

専門家の検証として、水島は「変数は箱とは教えない」と宣言した言語処理系のコースを重点的に読み「ごまかしも誤りも見つけられなかった」とし、左結合の説明や「評価器へのかけ算追加は1行、大変なのは文字列から木を組む側」といった処理系を書いた人間が頷く記述まで含まれていた点を「やさしさと正確さを両立している」と評価した。**肌感程度の指示から設計判断の連鎖を自走させ完成品に到達する**ことが、Fable 5 のループ型の使い方の到達点を示している。

## セーフガード設計（一般公開を可能にした核心）

Fable 5 の分類器が**サイバーセキュリティ・生物化学・蒸留**に関わるリクエストを検知すると、応答は自動的に [[models/claude-opus-4-8|Opus 4.8]] に肩代わりされ、ユーザーに通知される（拒否でなくフォールバック）。

- **95%超のセッションでフォールバックなし** → その場合 Fable 5 の性能は Mythos 5 と実質同等
- セーフガードは保守的にチューニングされており、benignなリクエストでも平均5%未満のセッションで誤発火
- サイバー分類器は exploit だけでなく偵察・横展開を含む agentic hacking 全般をカバー。1,000時間超の外部bug bountyでもuniversal jailbreak は発見されず（UK AISI が初期テストで一部進展）
- 生物化学は当面broadにOpusへフォールバック（Dyno Therapeutics の未公開AAVカプシド組立予測で protein language model を上回ったことが dual-use リスクの根拠）

## 問い

- 5%未満の誤発火は実用上どの程度ストレスか。サイバー/生物に隣接する正当な作業（自分のセキュリティレビュー・[[concepts/claude-code-security]]等）でフォールバックが頻発しないか
- フォールバック時に Opus 4.8 へ落ちる挙動を、コーディングワークフローでどう検知・設計するか（モデルスタッキングの観点）
- 「数ヶ月を数日に圧縮」は自分の中規模コードベースでも再現するか、それとも大規模Rubyのような特定条件下の話か
- 「計画と骨格は Fable 5、細部は Opus/Sonnet」の引き継ぎ点はどこで切るのが最適か。基盤完成後の追加作業を軽量モデルに渡すコスト最適化を自分のプロジェクトで設計できるか
