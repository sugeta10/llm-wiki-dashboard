Claude の 20 機能地図（チャット内・役割・チャット外・開発者・応用）

TL;DR: チャットを開いて聞き、答えをコピーして閉じる使い方を「Claude の 10%」と呼び、チャット内の 4 機能・役割プロンプト 5 種・チャット外の 7 機能・開発者向け 1 項目・応用 3 項目の計 20 を「どこにあるか・どう有効化するか・今日試すプロンプト」の 3 点で並べた @angeldot_ のスペイン語ガイド（X 記事「Claude hace todo esto (y casi nadie lo sabe)」・4,085 ブクマ）。

@angeldot_ は、多くの人が Claude をテキスト生成器としてしか使わず、記憶・チャット内で動くアプリ・寝ている間に走るタスク・ブラウザ操作に触れたことがないと書き、各機能は数分で設定でき、以後は毎日時間を返す、と述べる。記事は 5 部構成で、各機能に貼り付け用のプロンプトを添えているが、プロンプト本文は画像で掲載されており本 vault のキャッシュには収録されていない。以下は本文の転記で、機能の説明は @angeldot_ の記述による。末尾で @angeldot_ は「全部を今日組もうとせず、1 つだけ選んで今設定せよ。何が存在するかを知ることが仕事の半分」と締める。

第 1 部: チャットにあるのに使われない 4 機能

  1. Projects（プロジェクト） — 新しいチャットは毎回ゼロから始まり、誰で・何をしていて・どう答えてほしいかを知らない。Projects を作って文書を上げ、固定の指示を書くと、そのプロジェクト内の全チャットで前提が保たれる。未使用ならここから始めよ、と @angeldot_ は書く
  2. Artifacts（アーティファクト） — 電卓・習慣トラッカー・ミニゲーム・グラフつきダッシュボードなど、チャット内で実際に動くものを作り、リンクで共有できる。SVG 図・ダイアグラム・インタラクティブな可視化も作る
  3. 拡張思考（razonamiento extendido） — 答える前に段階的に分析し、その過程が見える。速い質問には不要で、複雑な決定・戦略分析で差が出る。同じ質問をオンとオフで比べよ、と @angeldot_ は勧める
  4. 記憶（memoria） — 設定で有効化すると、職業・進行中のプロジェクト・好む話し方を保存し、新しいチャットでも文脈を持って始まる。急ぎたければ自分から直接伝えればよい

第 2 部: 役割を与えると別物になる 5 プロンプト

@angeldot_ は、具体的な役割を与えると Claude が投げる質問・反論する点・見逃さない点が変わると述べ、新しいチャットの冒頭に貼る 5 種を挙げる。

  1. 考えさせる心理士 — 「大変ですね」と一般的な助言 5 つを返す既定の応答を、認知行動療法の治療者に近い振る舞い（助言でなく質問し、同意でなく思考の型を問う）に変える。堂々巡りの決定や状況を外から見るのに使う。本当に辛いときの専門家の代わりにはならない、と @angeldot_ は注記する
  2. 忖度なしのメンター — Claude は既定で相手の案に乗って良い点を探すが、計画の検証にはそれが邪魔になる。弱い仮定・考慮漏れ・計画が壊れる正確な点を探させる。「沁みる。だから効く」と書く
  3. パーソナルトレーナー — 一般的なトレーニング計画は予定・怪我・器具・本当の目標を考慮しない。自分のデータを渡して計画を組ませ、経過を伝えて調整させる
  4. 難しい会話の予行 — 言いたいことは分かっても相手の返答は分からない。Claude に相手役を演じさせ、弱い論には反論させて結果を勝ち取らせる。2〜3 回の予行で本番の負担が下がる
  5. 悪魔の代弁者 — 決めて、難点も考えて、確信している。その瞬間に決定を攻撃させる。礼儀正しい「懸念」でなく、反対の論の全体と、最も現実的な失敗の仕方を 3 つ。着手の 5 分前に、後でなく

第 3 部: チャットの外で動く Claude

  1. Claude in Chrome — 開いているタブに Claude を入れる拡張。ページを読み、クリックし、フォームを埋め、別 URL へ移動する。Chrome Web Store で「Claude」を探して入れ、アカウントでサインインしてアイコンからサイドパネルを開く
  2. 自分のコンピュータのファイル — Web 版は PC の中を見ない。デスクトップアプリでフォルダを接続すると、実ファイルを読み・文書を編集し・新規作成し・フォルダを整理する。長いタスクを任せて最終結果だけ受け取れる。以前は別アプリ（Cowork）だったものが Claude に直接統合された、と @angeldot_ は書く
  3. 予定実行タスク — 一度設定すれば毎朝・毎週月曜・毎時に自分で走る。チャットで頼むだけでよい
  4. Skills — 特定の種類のタスクのやり方を教える指示のパッケージ。PowerPoint 作成・PDF 処理・会社の業務フローなどを一度入れれば毎回説明しなくてよい。「スマホはアプリ無しでも動くが、適切なアプリでできることが増える」と例え、同梱のもの・組織のもの・繰り返す作業から Claude に作らせるものの 3 経路を挙げる
  5. CLAUDE.md — Claude Code でプロジェクトのフォルダに置くと、各セッションの開始時に頼まなくても読む。コード規約・文体ルール・社内用語・ブランドの声を一度書けば全セッションで従う
  6. Claude Code — 断片でなく機能全体・複雑なリファクタ・本番向けコードを書く。開発環境の中で、コードを読み・新規に書き・テストを走らせ・エラーを読んで直す、を終わるまで繰り返す。ターミナル・Web・デスクトップアプリ・モバイルで使え、VS Code と JetBrains に統合され、GitHub Actions に入れて PR のレビューや作成を無人で回せる、と @angeldot_ は書く
  7. デザイン — ワンページャー・プレゼン・プロトタイプ・アプリ画面・LP を、説明すると編集可能なキャンバス上に作り、必要な形式で書き出す。デザイナーでない人にとって「Figma の 3 時間が 10 分の会話になる」と @angeldot_ は書く

第 4 部: 開発者向け

  1. プロンプトキャッシュ — API 呼び出しが大きな文脈ブロック（長い system prompt・参照文書・コードベース）を繰り返すなら、毎回同じトークンを処理する料金を払っている。キャッシュ対象のブロックに "cache_control": {"type": "ephemeral"} を付けると、キャッシュされたトークンは最大 90% 安く、応答も速くなる。既定の保持は 5 分で、使うたびに更新される。system prompt・長文書・ツール定義に効く。「規模で作っていて使っていないなら金を捨てている」と @angeldot_ は書く。仕様の詳細は prompt-caching にある

第 5 部: 意外な使い方

  1. 動画編集 — タイムラインでなく、コード（多くは ffmpeg）を書いて実行することで編集する。Claude Code と、ファイルを扱うアプリで動く。できることとして、切り出し・結合・無音除去／横動画を Reels・TikTok・Shorts 向けの縦 9:16 へ／音声抽出・圧縮・形式変換／速度変更・GIF 化／同じ設定で 50 本の一括処理を挙げる。創作的な編集で Premiere の代わりにはならないが、反復作業では時間を返す、と書く
  2. コネクタ — 既定ではメールも予定も見ない。設定から Gmail・Google Calendar・Drive・Notion 等をつなぐと、検索・読解・横断ができる
  3. 写真から表へ — 画像理解の応用。レシートや請求書の写真→品目・金額・税（IVA）の表／エラーのスクリーンショット→原因と直し方／ホワイトボードの写真→タスクつきの整理／気に入った Web のスクリーンショット→HTML のモックアップ

位置づけ（wiki 側の読み）

  • 同じ「10% しか使っていない」から始まる claude-best-practices（@AnatoliKopadze の 18 ステップ）がチャット内のプロンプト術に寄るのに対し、本ページは Chrome・デスクトップ・予定実行・Claude Code・API まで面を横断する機能の所在一覧で、両者は「どう頼むか」と「どこに何があるか」で補い合う
  • 第 2 部の「忖度なしのメンター」「悪魔の代弁者」は、ai-red-teaming が敵対ペルソナに自社を攻撃させる手法の個人版で、Claude が既定で相手の案に乗る性質（2023-sharma-sycophancy が示す迎合）を役割指定で外す使い方と考えられる
  • 第 3 部の 11（Cowork 統合）・12（予定実行）・16（デザイン）は製品側の機能で、本 vault では公式発表のページを持たない。@angeldot_ の記述が唯一の根拠なので、公式ドキュメントで提供状況を確かめてから頼るのがよい
  • 動画編集の項は、ffmpeg を Skill に固めた ffmpeg-skill と、Claude Code と会話で編集する OSS video-use の「素のまま使う」側に当たる
