# Attention（アテンション機構）

> **TL;DR**: Transformer の中核。各トークンの「文脈を含まない汎用埋め込み」を、周囲のトークンから情報を引き込んで「文脈に富んだ埋め込み」へ更新する仕組み。2017年の論文 *Attention is All You Need* で登場。

LLMのゴールはテキストの続きを予測すること。入力はトークンに分解され、各トークンはまず高次元ベクトル（埋め込み）へ対応付けられる。この最初の埋め込みは**文脈を考慮しない参照表**にすぎず、同じ単語（例: "mole"＝モル/ほくろ/モグラ）はどの文でも同一ベクトルになる。アテンションは「形容詞が直前の名詞の意味を調整する」「Eiffel の直後の Tower をパリ・鋼鉄の方向へ動かす」といった具合に、文脈の関数として埋め込みに加算すべき変化量 ΔE を計算し、汎用ベクトルを具体的な方向へ移す。これを何層も繰り返すことで、各埋め込みは単語そのものより遥かに豊かな意味（感情・トーン・背後の事実など）を吸収していく。

## 仕組み（Query / Key / Value）

3つの**学習可能な行列**でできている。

1. **Query（W_Q）**: 各埋め込みに掛けて、より小さな次元（例: 128次元）のクエリベクトル Q を作る。概念的には「私の前に形容詞はある？」のような“問い”
2. **Key（W_K）**: 各埋め込みに掛けてキーベクトル K を作る。クエリへの“答え”の候補。あるトークンのキーが別トークンのクエリと**揃って（内積が大きく）**いれば、前者が後者に「アテンドしている」
3. **Value（W_V）**: あるトークンが別トークンの意味調整に関わるとき、その埋め込みに何を足すべきかを表す Value ベクトルを作る

**アテンションパターン**: 全クエリ×全キーの内積表を作り、計算安定化のためキー/クエリ空間次元の平方根で割り、**列ごとに softmax** で正規化する（各列が0〜1で合計1の確率分布）。この重みで Value ベクトルの重み付き和を取り、ΔE として元の埋め込みに加算する。

- **マスキング（causal）**: GPT系では「後ろのトークンが前のトークンに影響を与えてはならない」（答えを漏らすため）。softmax前に該当成分を**−∞**にすると、softmax後に0になりつつ列の正規化は保たれる
- **計算量はコンテキストサイズの2乗**になり、これが長文脈スケールの大きなボトルネック。近年は各種バリエーションが提案されている
- **Value の低ランク分解**: Value写像は「Value down（大きな埋め込み空間→小さな空間）」と「Value up（小さな空間→埋め込み空間）」の2行列に分解でき、パラメータ数をKey/Queryと揃えると効率的。実装では各ヘッドの Value up をまとめた巨大な **Output 行列** として現れることが多い（論文の表記では「Value 行列」が Value down だけを指すことも）

## マルチヘッド & スケール

ここまでは**シングルヘッド**。実際の Transformer は**マルチヘッドアテンション**で、異なる Q/K/V 写像による演算を並列実行し、文脈に応じた意味更新の様々なパターンを同時に学習する。各ヘッドが提案する ΔE を全て足して元の埋め込みに加算する。

- GPT-3: 1ブロックあたり**96ヘッド**、ヘッド1つあたり約63万パラメータ、全**96層**。アテンション全体で約580億パラメータ（ネットワーク全体1,750億の約1/3）
- アテンションの成功要因の核心は具体的な振る舞いより**並列化のしやすさ** —— GPUで膨大な計算を短時間でこなせること。「スケールだけで大きな質的改善が見込める」という深層学習の知見を、並列化可能なアーキテクチャが実現可能にした
- **Self-attention**（Q/K/Vが同一データ）に対し、**Cross-attention** はQとKが異なるデータに働く（例: 翻訳元↔翻訳先、音声↔文字起こし）。Cross では後続トークンの影響を防ぐ必要がないため通常マスキングしない

## 問い

- O(n²) ボトルネックを緩和する近年のアテンション変種（線形アテンション・スパース等）は、長文脈での品質をどこまで保てるか
- KV キャッシュ（[[concepts/prompt-caching]]）は Key/Value の再計算を省くものだが、アテンション機構のどの部分が具体的にキャッシュ対象になるか
- この基盤理解は、自分のLLM活用（プロンプト設計・コンテキスト管理）の判断にどう効いてくるか
