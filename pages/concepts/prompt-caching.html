プロンプトキャッシング（Prompt Caching）

Anthropic Claude APIが提供するプロンプトの前処理結果を再利用する機能。同一のプレフィックスを含むリクエストで、処理時間とコストを大幅に削減できる。

関連: prompt-cache-prewarm | prompt-engineering | anthropic

キャッシュの有効化方法

自動キャッシュ（推奨）

リクエストのトップレベルに cache_control を1つ追加するだけ。マルチターン会話で最後のキャッシュ可能ブロックに自動でキャッシュブレークポイントを適用し、会話が伸びるにつれて自動で前に進む。

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    cache_control={"type": "ephemeral"},
    system="...",
    messages=[...]
)

明示的キャッシュブレークポイント

個別のコンテンツブロックに cache_control を直接配置する方法。変更頻度が異なる複数セクションをキャッシュしたい場合や、精密な制御が必要な場合に使う。最大4箇所まで設定可能。

キャッシュ参照の順序: tools → system → messages

仕組み

  1. リクエスト送信時、指定されたキャッシュブレークポイントまでのプレフィックスがキャッシュに存在するかチェック
  2. キャッシュヒット → 前処理をスキップして応答生成
  3. キャッシュミス → フルプロンプトを処理し、キャッシュに書き込んでから応答生成

デフォルトTTL: 5分（リクエストのたびに無料で更新される）。1時間TTLも別料金で利用可能。

価格（Claudeモデル共通の倍率）

種別 倍率（ベース入力トークン比）
5分キャッシュ書き込み 1.25倍
1時間キャッシュ書き込み 2倍
キャッシュ読み込み 0.1倍
通常入力 1.0倍

ルックバックの仕組み（明示的ブレークポイント）

  • キャッシュ書き込みはブレークポイントの位置のみ
  • キャッシュ読み込みはブレークポイントから最大20ブロックさかのぼって検索
  • よくある誤り: タイムスタンプや毎回変わる内容のブロックにブレークポイントを置くとヒットしない。静的プレフィックスの末尾に置くのが正しい

キャッシュが無効化されるトリガー

変更内容 影響範囲
ツール定義の変更 tools + system + messages 全無効
web search / citations ON/OFF system + messages 無効
tool_choice の変更 messages のみ無効
画像の追加・削除 messages のみ無効

キャッシュ対象・非対象

キャッシュ可能: tools定義、system、テキスト/画像/ドキュメント/tool use/tool results

キャッシュ不可: thinking ブロック（直接指定不可。ただし前のターンとして渡すと間接的にキャッシュされる）、サブコンテンツブロック（citations等）、空テキストブロック

パフォーマンスの追跡

レスポンスの usage フィールドで確認: - cache_read_input_tokens: キャッシュから読み込んだトークン数 - cache_creation_input_tokens: 新たにキャッシュに書き込んだトークン数 - input_tokens: 最後のブレークポイント以降のトークン数（これだけでは全体ではない）

総入力トークン = cache_read + cache_creation + input_tokens

ベストプラクティス

  • マルチターン会話 → 自動キャッシュから始める
  • 変更頻度の異なる複数セクション → 明示的ブレークポイントを使い分ける
  • 静的コンテンツ（システムプロンプト・ツール定義・大量コンテキスト）をプロンプトの先頭に配置
  • 会話が20ブロック以上伸びる見込みなら2つ目のブレークポイントを事前に設定しておく
  • 1時間キャッシュは「5分以上間隔が空くが1時間以内に再利用する」用途に最適

キャッシュ分離

2026-02-05以降、Claude APIはワークスペース単位でキャッシュ分離（従来は組織単位）。Bedrock/Vertex AIは引き続き組織単位。
