# 開発者×AIエージェントの役割分担哲学

韓非子「主道篇」の政治哲学を [[tools/claude-code]] 活用に適用した、開発者とAIエージェントの最適な協働パターン。

## 核心概念

開発者が担うべきは「過程」ではなく「結果」への責任。

| 役割 | 担うもの |
|------|---------|
| Claude Code | コーディング・分析・設計提案・選択肢の生成（過程） |
| 開発者 | 何を作るか・何が良いかの評価・採否・失敗への対応（結果） |

## 主道篇から学ぶ原則

### 1. 開始と終了だけを抑える

プロジェクト開始（何を作るかの決断）と最終成果物の受け入れ判断だけは開発者が担う。その中間では Claude Code に任せて待つのが理想。

### 2. 形名参同（けいめいさんどう）

事前の Plan で定義した成功基準と、実際の成果物の測定結果を一致させて確認すること。

「作業完了しました」で受け入れてはならない。テスト結果の実数・ベンチマーク数値・実行ログで確認する。

### 3. 好みと意図を見せない

- **好みを見せると**: Claude Code はそれに合わせて最適でない成果物を出す
- **意図を見せると**: Claude Code は意図に沿った説明を「自分の意見」として偽装する
- **知恵を見せると**: Claude Code の探索範囲が狭まる

LLM は RLHF で人間の好みに合う回答をするよう訓練されているため、人間の部下より注意が必要。

### 4. 制約条件は明確に、内心は隠す

事実・制約（「本番環境はPython 3.9」「締め切りは今日中」）は明確に伝える。  
開発者の欲・意（好み・意図・先入観）は出さない。

## 実践パターン

**悪い例（意図を示す）:**
- 「この方法でOK？」→ 肯定方向に誘導してしまう
- 「これで実装して」→ 選択肢を消す

**良い例（探索させる）:**
- 「異なるアプローチを3通り以上出して、トレードオフを分析せよ」
- 「この設計の問題点を可能な限り列挙せよ」
- 「成功基準を明確にせよ」「何をもって完了とするか事前に定義せよ」

## 習常（じゅうじょう）：型化された運用状態

- セッションはタスクごとに独立
- ルーチン作業は Agent Skill で定型化
- タスク難易度に応じてモデル・effort を切り替え

この状態になると開発者は個別に指示しなくても意思が反映され、実際に手を動かすことが減っていく。

## 自己改善ループとの統合

Agent Skill を自己改善させることで処理能力を継続向上。失敗はコンテキストやハーネスの改善契機として活用（[[concepts/self-refining-skills]] 参照）。
