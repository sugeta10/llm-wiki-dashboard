AI 専用スマホ：Pixel を 1 台 AI に渡して LINE アプリを操作させる運用（いち）

TL;DR: 経営者のいち（@ichiaimarketer）が、整備済みの Pixel 8a を 1 台 AI 専用にして Mac に USB で接続し、USB デバッグを有効にした上で Claude Code などの AI に画面の文字を読ませてボタンを押させ、LINE のオープンチャットへの告知と動画送信・グループや個別への返信・友だち 527 人のラベル付けを任せている運用。送信前に相手の名前・相手から最後に届いたメッセージ・原稿の全文を AI が突き合わせ、本人の「送っていい」が無ければ送信そのものが動かない仕組みを置く。紹介したテツメモ（@tetumemo）は「任せる範囲の広さより、送信を止める仕組みの方がこの運用の本体」と読む。

スマホを 1 台渡す理由をいちは「AI がスマホの画面を読んで、LINE アプリをそのまま操作できるから」と説明し、「パソコン版の LINE では、ここまで任せられない」と述べる（理由は投稿に書かれていない）。Mac 側のカーソルは奪われないので本人の作業は止まらず、機種は整備済みの Pixel 8a で「高い機種は要らない」とする。締めの「AI に働かせるなら、スマホも AI 専用を 1 台」が投稿の主張で、いちの X プロフィールは AI 社員の構築支援を法人向けに案内しており（売上・M&A の数字は自己申告）、投稿はその発信の一部である。テツメモは AI の図解と検証を発信するニュースレター運営者で、引用で「安全側の仕組み」として送信前の決まりを抜き出した。

任せている仕事（いちの転記）

  • オープンチャットへのお知らせと動画の送信
  • グループや個別への返信
  • 友だち 527 人を見て、95 人の表示名に「ビジネス」「友人」などのラベル付け

送信前の決まり（いちの転記）

  • 送る前に、相手の名前・相手から最後に届いたメッセージ・原稿の全文を AI が突き合わせる
  • 本人の「送っていい」が無ければ、送信そのものが動かない仕組みにしてある

接続の条件（いちの転記）

  • Pixel を Mac に USB でつなぎ、設定の「開発者向けオプション」で USB デバッグをオンにする（最初にやるのはこれ）
  • Claude Code などの AI が、画面の文字を読んで必要なボタンを自分で押す
  • Mac のカーソルは奪わないので、自分の作業は止まらない

仕組みの読み（wiki 側の推論）

投稿は道具の名前を USB デバッグと Claude Code しか出していないので、以下は wiki 側の推論である。USB デバッグを有効にした Android 端末は、ホスト側から Android Debug Bridge（adb）で操作できる。adb には画面上の UI 階層（各要素のテキスト・種類・座標）をテキストで取り出すコマンドと、座標をタップする・文字を入力する・キーを送るコマンドがあるので、「画面の文字を読んでボタンを押す」は、スクリーンショットを画像として見るのでなく、この UI 階層のテキストを読んで座標を押す経路で実現していると考えられる。この経路なら Mac のマウスとキーボードは一切使わないため、「カーソルを奪われない」も同じ機構で説明がつく。スクリーンショットを使わず要素のテキスト表で操作する点は、ブラウザ向けの jev-ultrafast と同じ発想である。

「パソコン版 LINE ではここまで任せられない」の理由は、PC 版を AI に操作させると Mac の画面とカーソルを人間と AI が取り合う点と、オープンチャットや友だちのラベル付けのような機能が PC 版で揃っているかの点の両方が考えられるが、投稿からは判断できない。

位置づけ（wiki 側の読み）

  • 送信だけ止める境界は、LINE 公式アカウントを MCP で Claude Code に運用させ送信系だけ人間確認に残す line-harness（@yagiryuuu）、仕事の入口を監視して「検知→調査→提案→人間確認→実行」に固定する ai-pre-judgment-automation（入江慎吾）と同じ線である。違いは置き場で、line-harness は API 層、入江は提案の承認、いちはアプリの送信ボタンを押す直前に「送っていい」の発話を要求する。送信前に相手名・直前のメッセージ・原稿全文を突き合わせる工程は、誤送信の典型（別人に送る・文脈違いの返信）を狙った検査と読める
  • API か画面操作か。line-harness と line-group-ai-crm は LINE 公式アカウントの API を使うので、届く範囲は公式アカウントの友だちに限られる。いちの方式は個人の LINE アプリを操作するため、オープンチャットや個人アカウントの友だち一覧（527 人のラベル付け）に手が届く。代わりに、個人アカウントの自動操作を LINE の利用規約が許すかという問題が生じるが、投稿はこの点に触れていない
  • 専用端末による分離は、grok-bot-team-guide で Lauren が勧める「Bot 専用のメールと Bot 名義のアカウント」の物理版にあたる。ただし分けているのは端末だけで、操作される LINE アカウントはいち本人のもの（友だち 527 人）と読めるので、端末は分離・アカウントは共有という構成である
  • 画面を操作する AIとしては、Anthropic の claude-computer-use がデスクトップとブラウザをスクリーンショットとマウスで操作するのに対し、本運用は専用のスマホを adb 経由のテキストで操作していると考えられる。対象をスマホに移したことで、スマホアプリしか無いサービスの操作が AI の手に入る
  • 承認線の置き方は、goal-process-automation で Lauren が「いつ助けを求めるべきかを Bot に質問させる」と Bot 側に委ねているのと対照で、いちは外部送信の直前に人間の発話を固定している

問い

  • LINE の利用規約は個人アカウントの自動操作（adb 経由の UI 操作）を許すか。公式アカウント＋API（line-harness）と比べ、規約リスクと到達範囲（オープンチャット・個人の友だち）のどちらを取るか
  • 「送っていい」の承認は Claude Code のどの機構で止めているか（ツール実行の確認プロンプトか、送信ボタンを押す手順だけを分けたスキルか）。投稿では実装は語られていない
  • 自分の環境で AI 専用端末を 1 台置くなら何に使うか。スマホアプリしか無いサービス（LINE・銀行アプリ・認証アプリ）の操作が候補で、どこまでを AI に渡し、どこで人間の発話を要求するか
