# Claude Code 作業フォルダ設計

Claude CodeはチャットAIではなく「作業フォルダの中でファイルを読み・編集・保存するAI」であるため、最初に整えるべきはプロンプトより作業場（ディレクトリ構成）だという初心者向けの設計原則（@kawai_design）。素材・参考資料・下書き・完成物が同じ場所に混在すると「何を読み、何を保存するか」が曖昧になり出力も散らかる。先に役割別の「棚」を作ることで、Claudeの参照先・保存先が一意に定まる。

これは [[concepts/obsidian-personal-os]] の8フォルダ固定構造（`00-CAPTURE`〜`07-ARCHIVE`）と同じ思想を、Claude Code単体・初心者向けに最小化したもの。両者とも「未整理の受け口」「参照ライブラリ」「生成物の隔離」「削除せずアーカイブへ退避」という原則を共有する。

## 最小構成（`claude-work/`）

| フォルダ | 役割 | Claudeへの指示の例 |
|---------|------|------|
| `inbox/` | 未整理の素材（文字起こし・メモ・URL一覧・思いつき）。使うか未定でも全部ここ | — |
| `reference/` | 参照してほしい情報（読者ペルソナ・タイトル候補・過去記事・ブランドルール・参考リンク）。出力の質は参照素材で変わる | 「reference/ を参照して」 |
| `draft/` | 下書き（記事案・構成案・確認前の出力）。完成物と混ぜない | — |
| `output/` | 完成物（note本文・投稿文・提案書）。使える状態のものだけ | 「完成物はoutputへ保存」 |
| `archive/` | 使い終わったものを削除せず移動。初心者は削除運用をしない方が安全 | 「不要素材はarchiveへ」 |
| `.claude/skills/` | プロジェクト用の設定・skills | — |
| `CLAUDE.md` | プロジェクトのルール定義 | — |

## 設計原則

- **役割の分離**: 未整理（inbox）・参照（reference）・途中（draft）・完成（output）を物理的に分け、Claudeの入出力先を明示する。
- **削除ではなく移動**: 完成・陳腐化したものは`archive/`へ退避。日常操作では参照しない。初心者ほど削除運用を避ける。
- **増やしすぎない**: 仕事別（note記事・議事録・調査など）にフォルダを足してよいが、最初は最小構成から。
- **プロンプトより先に棚**: 「作業場が整うほど使いやすくなる」——プロンプト最適化はその後。
