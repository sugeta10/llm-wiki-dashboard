# Claude Codeに業務を渡す（環境設計発想）

> **TL;DR**: Claude Codeを「賢い質問箱」でなく業務フローごと渡せる作業者として使うための活用法50個と、その根底にある「毎回うまく指示する」から「指示なしでも良い結果が出る環境を一度設計する」への発想転換。

使いこなす人と持て余す人を分けるのはスキルや知識量ではなく、AIに毎回ゼロから頼むか／頼まなくても同じ品質が出る前提（CLAUDE.md・Skills・Hooks・カスタムコマンド）を一度作り込むかの差にある。単発で「要約して」「返信を書いて」と質問して出力をコピペする使い方は、AIを使い捨ての作業者のまま留める。対して「ファイル整理・メール分類・集計・資料作成といった業務フローそのものを渡す」運用は、一度の仕込みがその後ずっと効く資産になる。

```mermaid
flowchart LR
  W1["第1週<br/>カテゴリ②ファイル整理<br/>で成功体験を1個"] --> W2["2〜3週目<br/>カテゴリ①③<br/>単発作業を渡す癖"]
  W2 --> M1["1〜2ヶ月目<br/>カテゴリ④<br/>CLAUDE.md/Skills資産化"]
  M1 --> M3["3ヶ月目以降<br/>カテゴリ⑤⑥<br/>上級ゾーン（環境設計）"]
```

## 50活用法の6カテゴリ

下に行くほど「作業を渡す」入口から「環境を設計する」応用へ移り、資産性が高まる。

| カテゴリ | 数 | 代表例 |
|---|---|---|
| ① 基本コマンド | 10 | `/plan` で計画だけ先出し・Plan modeで承認待ち停止・`/rewind` で巻き戻し・[[concepts/claude-md-rules]] にルール記述・カスタムコマンド化・`/clear` で文脈リセット・`@ファイル名` で範囲限定・Hooksで危険削除をブロック |
| ② ファイル整理 | 8 | Downloads自動分類・表記ゆれ一括リネーム・重複検出・古いファイルをArchive退避・PDF中身で分類。**消さずに候補一覧→人が承認**が事故防止の核 |
| ③ メール・Slack連携 | 8 | 受信メールを重要度別に分類・返信要のみ抽出・自分の文体で下書き・長スレッド3行要約・議事録から自タスク抽出 |
| ④ 文書・資料作成 | 8 | メモから報告書を組み立て・CLAUDE.mdの文体ルールで統一・文字起こしから議事録・1ページ要約・上司向け/顧客向けに書き分け |
| ⑤ 定期作業の自動化 | 6 | 売上CSVから週次レポート・集計手順をSkills化・KPI集計をワンコマンド・ログから異常値抽出 |
| ⑥ 上級者の使い方 | 10 | サブエージェントで複数仮説を並列検証・役割分担させ結論を突き合わせ・[[tools/claude-mcp]] で外部ツール連携・CLAUDE.md階層化・業務フロー全体を1ワークフロー化・作るAIと確認するAIを分離 |

## 事故れない仕組みを先に作る

「AIに自分のフォルダを触らせる」抵抗感への答えは根性論でなく仕組み化。`/plan` で触るファイル・手順・リスクを承認まで止め、Plan modeで停止、暴走しても `/rewind` で巻き戻し、重要ファイルはバックアップ前提、Hooksで危険な削除を実行前にブロックする。逃げ道があると分かると人は踏み出せる、という導入設計の論理になっている。この発想は [[concepts/claude-code-work-folder]] の「プロンプトより先に棚（作業フォルダ）を作る」と地続きで、[[tools/claude-code]] を安全に任せるための前提整備にあたる。
