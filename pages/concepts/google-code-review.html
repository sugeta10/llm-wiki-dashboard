Google コードレビュー指針

TL;DR: Google が CC-By 3.0 で公開するコードレビュー指針（レビュアー視点と作成者視点の2文書）は、人間のレビュー基準をドキュメント化したものであり、AIエージェントへの「レビュー仕様」としても再利用できる。

指針は「コードを読む側」と「コードを出す側」という非対称な2つの立場に分けて記述されており、同じレビューという行為を双方向から規定しているのが特徴である。具体的には次の2文書に分かれる。

  • The Code Reviewer's Guide — レビュアー視点: 何を見るか・どう指摘するか・LGTM基準
  • The Change Author's Guide — 作成者視点: CLをどう設計するか・レビュアーとどうやり取りするか

両ガイドは Google 内部語で記述される。

用語 意味
CL（Changelist） バージョン管理に提出された1つの自己完結した変更。他組織での PR / patch / pull-request に相当
LGTM "Looks Good to Me" — レビュアーが CL を承認するときのサイン

AI時代との接点

AIエージェントがコードを自律生成・レビューする agentic-coding の文脈で、人間のコードレビュー基準をドキュメント化したこの指針は「AIへの指示仕様」としても再利用できる。spec-driven-development の観点からは、レビュー基準を機械可読な形式で保持することがエージェント品質管理に直結する。

Claude Codeスキルとしての活用

このリポジトリ全体を claude-code の スキル として投入すると、エージェントが書く PR の品質管理にレビュー基準を直接参照させられる。指針には「レビュアー視点（何をチェックされるか）」と「作成者視点（PR をどう小分けにして説明文を書くか）」の両技術基準がまとまっているため、PR の粒度や説明文の質を改善する仕様として機能する。スキル化すれば、必要な部分だけをエージェントに読ませる効率化も可能になる。
