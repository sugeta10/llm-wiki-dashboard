AI Engineer ロードマップ（2026）

2026年時点での AI エンジニアとして学ぶべきこと・作るべきもの・スキップすべきことの整理。

学ぶべきこと

  • LLM API の活用: OpenAI / Anthropic / Google の API 設計と特性の違い
  • プロンプトエンジニアリング: prompt-engineering の基礎から応用
  • エージェント設計: ループ制御・ツール呼び出し・エラーリカバリー（agentic-coding）
  • RAG（検索拡張生成）: ベクトル DB・チャンク設計・リランキング
  • 評価（Eval）: LLM 出力の品質を定量的に測る手法

作るべきもの

  • 自分のユースケースに特化したエージェント（汎用より専用が価値大）
  • 社内 LLM Wiki / ナレッジベース（llm-wiki）
  • CI/CD に組み込んだ自動コードレビュー
  • データパイプライン（取得・変換・要約の自動化）

スキップしてよいこと

  • モデル学習・ファインチューニング: API で十分なケースが大半。コストと時間が見合わない
  • 独自ベクトル DB 構築: 既存サービス（Pinecone・Weaviate 等）で事足りる
  • フルスタック AI フレームワーク: LangChain 等は学習コスト高。シンプルな API 直呼びの方が制御しやすい

2026 年の潮流

「What to Learn, Build, and Skip in AI Agents (2026)」（@rohit4verse）より： - エージェントは「賢い自動化」ではなく「自律的な判断主体」として設計する時代 - ハーネス設計（claude-harness）が差別化要因 - 評価（Eval）がボトルネック — 作れるエンジニアが少ない
