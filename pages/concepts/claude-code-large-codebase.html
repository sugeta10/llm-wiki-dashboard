Claude Code 大規模コードベースのベストプラクティス

Anthropic公式ベストプラクティスに基づく、大規模コードベースでのClaude Code活用指針。精度はモデルよりハーネスの整備で決まるというのが根幹の主張。

関連: claude-code | claude-md-rules | agentic-coding | understand-anything

Claude Codeはインデックスを作らない

RAGツールと異なり、Claude Codeはコードベース全体をベクトル化しない。代わりにファイルツリーをたどり、grepで必要箇所を探す（= 常にライブのコードベースを見る）。

これは古いインデックスを参照するリスクを排除する一方、「どこを見ればいいか」の手がかりがないと探索でコンテキストを使い切るリスクがある。CLAUDE.mdとハーネス整備がその手がかりを与える。

ハーネスの5層

層 役割
CLAUDE.md 文脈
hooks 自動化
skills 専門知識
plugins 配布
MCP 外部ツール接続

積む順番が重要: 土台（CLAUDE.md → hooks）が固まってから skills/plugins/MCPを足す。いきなりMCPを生やすと不安定になる。

CLAUDE.md の設計原則

  • ルートは薄く: 全体像と「ここを踏むと事故る」ハマりどころだけ
  • ローカル規約はサブディレクトリに: Claude はディレクトリを下りながらCLAUDE.mdを順に積み上げるため、深い階層の文脈もちゃんと届く
  • 定期的な棚卸し: モデルが進化すると古いルールが足かせになる。3〜6ヶ月ごと、または大きなモデルアップデート後に見直す

起動位置: ルートではなくサブディレクトリ

タスクに関係するサブディレクトリでClaude Codeを起動すると精度が出る。親ディレクトリのCLAUDE.mdは自動で読まれるため、コンテキストは失われない。サブディレクトリのCLAUDE.mdにはそのサービス固有のテスト・リントコマンドを書く（全スイート実行のタイムアウトとコンテキスト汚染を防ぐ）。

hooks の真価: 自己改善ループ

hooks の主な用途は「止めるスクリプト」ではなくセットアップを育てること:

  • stop hook: セッション終了時にその回の学びをCLAUDE.mdの更新案として出力。文脈が新しいうちに反映できる
  • start hook: セッション開始時にチーム固有の文脈を動的に注入
  • リント・フォーマットは hooks で機械的に実行 → 「覚えといてね」より安定

個人開発者向けの絞り込み

エンタープライズ向けの「専任チーム・DRI・エージェントマネージャー」は不要。

やることのシンプルな順序: 1. CLAUDE.mdをルートとサブディレクトリに分けて薄く整える 2. stop hookを1つ入れて自己改善を回す 3. 土台が安定したらskills/plugins/MCPを追加

古い設定は能力を制限する

「リファクタは1ファイルずつ」といった古モデル向けの制約が、最新モデルではかえって能力を殺すことがある。設定の棚卸しは定期的に。
