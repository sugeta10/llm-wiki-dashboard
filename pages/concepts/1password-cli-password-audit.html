1Password CLI × Claude Code で手持ちのパスワードを総点検する

チャエン（@masahirochaen・株式会社デジライズ CEO）が 2026-10-25 に「今流行りの『1Password × CLI』、自分もやってみました」として投稿した実践。持っているパスワード 1,116 件をすべて 1Password に入れ、Claude Code で 1 件ずつレビューするダッシュボードを自作した。1Password CLI は、保管庫の項目をターミナルから読み書きする 1Password 公式のコマンドラインツールで、Claude Code のようなコーディングエージェントから保管庫のデータに触る入口になる。

チャエンのダッシュボードは、各アカウントを次の 5 観点で点数化する。

  • 漏えい済み
  • 使い回し
  • 弱いパスワード
  • 2 段階認証が未設定
  • AI サービスの要注意アカウント（何を要注意とするかの基準は本文に無い）

カードの「まとめて対応」を押すと危ない順に変更画面が開く。1Password 純正のダッシュボードもあるが、自作だと「そのまま実行までできる」「カスタマイズできる」点が気に入っていると述べる。全体スコアは最初 30 点で、1 日集中して作業し 73 点まで上げたという（添付画像はデモ用に架空の数値で作ったと本人が断っている）。

発端となった GOROman の投稿

チャエンが「参考にさせていただきました」と引用したのは、GOROman（表示名 NULL=RUN・元 Meta / Oculus / セガサミー）が同日に投稿した 2 件である。GOROman は「Claude Code を使って 1Password に登録されているアカウント（516 個）のパスワードを全部変えたり、自動で解約するツールを作っている」と書き、数時間後に「Claude Code + 1Password CLI でパスワード自動変更システム」と続けた。いずれも本文は短く、仕組みの詳細は添付画像のみで本 vault では未収集。

2 人の投稿を並べると、同じ「1Password × CLI」でも狙いが違う。GOROman は変更と解約という実行そのものの自動化を目指し、チャエンは点数化と優先順位づけまでをツールに任せ、変更画面を開くところで人間に手を渡す。

構造の読み（wiki 側）

1Password が各アカウントの現状（漏えい・使い回し・強度・2 段階認証の有無）を持ち、Claude Code が CLI 経由でそれを読んで「次に何を直すか」を順序づけ、変更画面を開くところまで進める、という分担と読める。純正の 1Password ダッシュボードは 1Password の Watchtower 機能を指すと考えられるが、原文は名指ししていない。

この型は 1password-for-agents と向きが逆である点に注意したい。1Password for Agents はエージェントにパスワードを見せずにサインインさせる仕組みだが、CLI でパスワードを扱う構成では、設計次第で Claude Code 自身が資格情報を読む位置に立つ。チャエン・GOROman の投稿はパスワード本体を Claude Code のコンテキストに通しているかを書いていないので、再現するなら項目のメタデータ（強度・漏えいフラグ・2 段階認証の有無）だけを読ませ、パスワード本体は人間側に留める設計を先に決める必要がある（wiki 側の注意）。

「今流行り」という言い方は、2026-10-21 の PHP 重大脆弱性の騒ぎ（php-critical-vuln-2026-10）で使い回しパスワードの変更と 2 段階認証が広く勧められた直後という時期と重なる。流行の発端がそこにあるかは投稿からは読めない（推測）。

問い

  • 自分の 1Password で、Watchtower 相当の漏えい・使い回し・2 段階認証の情報を CLI から項目ごとに取れるか。取れるなら、パスワード本体を読まずに点数化できる
  • GOROman の「自動で解約するツール」はサイトごとの解約フローをどう扱うのか。画像のみで未収集なので取り直す
  • 点数（30→73）はチャエン独自の重みづけである。自分で作るなら、どの観点にどれだけ重みを置くかを先に決める
