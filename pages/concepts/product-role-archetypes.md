# プロダクトの5アーキタイプ（職能でなく価値創出の局面で人を見る）

> **TL;DR**: エンジニア・PM・デザイン・DS といった職能が一つの新しい役割へ融け合う中で、仕事は Prototyper / Builder / Sweeper / Grower / Maintainer の5アーキタイプに分かれる。役割は職種に紐づかず、健全なチームはプロダクトの成熟段階に応じてこれらを配合する。

> 📌 X bookmark: 13,254（2026-06-29 時点）

軸が「あなたは何の職種か（エンジニアかPMかデザイナーか）」から「プロダクトのライフサイクルのどこで価値を生むか」へ移る、という見立てである。同じ職種の中にも異なるアーキタイプが混在し、逆に異なる職種が同じアーキタイプに収まる。だから将来のプロダクト役割は、今日のようなドメイン特化の肩書きでなく、この局面ベースの分類に近づくのではないか、というのが核心の問いになる。

5つのアーキタイプ:

1. **Prototyper**: まったく新しいアイデアを出す。大量に生み出すが、その多くは出荷されない
2. **Builder**: プロトタイプやアイデアを素早く本番品質のプロダクト／インフラへ仕上げる
3. **Sweeper**: UIを磨き、コードとシステムを単純化し、不要機能を畳み（unship）、性能を最適化する
4. **Grower**: 作られたプロダクトを反復改善し、プロダクトマーケットフィット（PMF）を高める
5. **Maintainer**: 成熟したシステムを所有し、規模拡大に耐える安全性・信頼性・速度・効率を保つ

多くの人は2つ、ときに3つのアーキタイプにまたがる。重要なのは、これらが職能（job function）に縛られない点で、デザイナーにもアーキタイプ1の人・2の人・3の人がいて、エンジニア・PM・DSでも同様だという。

健全なチームはプロダクトの段階に応じて配合を変える:

| プロダクトの段階 | 必要なアーキタイプの配合 |
|---|---|
| 新規・PMF前 | 1+2+3 に強い人 |
| 成長中・PMF達成 | 2+3+4 |
| 強いPMF・規模拡大 | 3+4+5 |

この分類は、価値評価の単位を「個人の役割」から「局面ごとの貢献」へずらす点で、人材を価値へ最適配置する議論（[[business/talent-to-value-ai]]）や、コード量でなく何を生んだかでエンジニアを見る AI時代のエンジニア像（[[concepts/ai-era-good-engineer]]）と同じ方向を向く。

## 観察ログ（未検証）

- 2026-06-28: Boris Cherny（@bcherny、Anthropic の [[tools/claude-code]] 作者）が、Claude Code チームを見て感じる5アーキタイプとして提示。エンジニア・プロダクト・デザイン・DS などが「新しい種類の役割」へ融け合いつつあるという観察が前提にある（本人の考察・将来予測を含む）。
- 2026-06-28: Anthropic 全体で、デザイナーにもアーキタイプ1/2/3の人がいて、エンジニア・PM・DSでも同じく職能とアーキタイプが一致しない、と本人が述べる（一次観察だが社内の主観的印象）。
- 2026-06-28: 「将来のプロダクト役割は今日のドメイン特化の役割でなく、こうした局面ベースに近づくのでは」という本人の予測。断定でなく問いの形で提示されている。
- 2026-06-30: @genmai_tokyo（個人アカウント）が5アーキタイプを日本語で二次解説し、AI時代のキャリア論へ展開。AIで一人が何役もこなせる時代でも最前線のClaude Codeチームに5つの型が残っていることを「ジェネラリスト最強論」への反証として提示している（二次まとめ・bookmark 914）。
- 2026-06-30: Prototyperの判断（まだ誰も試していないことを試す価値があるか＝リスクを取る）とMaintainerの判断（この変更がシステムを壊さないか＝リスクを排除する）は真逆で、AIは作業を速くしても思考の癖は変えられない。一人で全部やるのはアクセルとブレーキを同じ人間が同時に踏むことで、どちらも中途半端になる、という@genmai_tokyoの解釈・比喩。
- 2026-06-30: 同記事によれば Boris Cherny は「健全なチームには型のミックスが必要だ」と明言（二次まとめ経由・原文の該当箇所は未確認）。「AI時代に肩書きの価値は下がるが型の価値は下がらない。AIが代替するのは作業であって型ではない」というキャリア論への拡張は@genmai_tokyoの主張。

## 問い

- この5アーキタイプは自分（一人＋エージェント群）の運用にも写せるか。wiki運用の中で自分はどの局面（新規ingest設計＝Prototyper/Builder か、lint・統廃合＝Sweeper か、Weekly育成＝Grower か）にどれだけ時間を割いているか。
- 「役割は職能に紐づかない」が正しいなら、エージェントにアーキタイプを割り当てる（探索担当＝Prototyper、実装担当＝Builder、整理担当＝Sweeper）設計は [[business/talent-to-value-ai]] のタスク=動詞割当とどう接続するか。
- 段階別の配合表は、自分のプロジェクト（PMF前か後か）に当てはめると今どのアーキタイプが不足しているかを示すか。
- 「肩書きでなく型で環境を選ぶ」を実践するなら、自分の型を一言で言語化できるか。それはリスクを取る側（Prototyper寄り）か排除する側（Maintainer寄り）か。
