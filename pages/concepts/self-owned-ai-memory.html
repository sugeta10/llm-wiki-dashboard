自己所有AIメモリ（モデル非依存の長期記憶を自作する）

AIとの会話と思考を毎回自分の手元のストアに要約・構造化して溜め、どのモデル・どのサービスを使っても同じ記憶を参照させる個人設計。起点は @kuwagata_no_isi が動画つきで公開した自作システムで、本人は「AIはモデルをなんにしようとサービスが終わろうがこうすりゃ一生自分の物になる」と位置づけている。記憶をベンダーのメモリ機能に預けず自分側に置くことで、モデルの乗り換えやサービス終了があっても蓄積が失われない、という主張である。動画本体は本vaultに未収集で、以下の構成は @_mumumu がその動画を見て要約したポストに基づく。@_mumumu は本人を「AIの記憶ガチ勢」と呼び、次元数などに「だか」「らしい」と留保をつけて書いているため、細部の数値は本人の一次情報で確認が要る。

記憶パイプラインの構成（@_mumumu の要約）

@_mumumu の要約によれば、システムは会話1回ごとに次の処理を通す。

  • 要約: 毎回の会話と思考を要約させる
  • ベクトル化: 要約を1024次元程度のベクトルに押し込む（@_mumumu は「1024次元だか」と留保をつけている）
  • カテゴリ分けとタグ付け: 各件に分類とタグを付ける
  • 関連付け: 件ごとに他の記憶と関連付ける
  • 忘却: 古い記憶は忘却曲線を使って処理する

これに加えて「無意識」に当たる層を設計しようとしており、常時動いていて人間が意識的に命令を送らなくても情報を取得し思考を関連付けているらしい、と @_mumumu は伝える。ユーザーの明示的な問いに応答する「意識的な想起」とは別に、バックグラウンドで記憶同士を結び直し続ける常駐プロセスを置く発想である。

別の実践者の同型実装（@zapabob_ouj）

@zapabob_ouj は @_mumumu のポストを引用し「わいのやってることとおなじやんけ」と述べ、自身の構成要素を列挙している。

  • セマンティックグラフ記憶
  • エビングハウス複合記憶
  • Obsidian での日記作成
  • ノードグラフ記憶の git 保存
  • 睡眠

各要素の中身はポストでは説明されていない。語の対応から、「セマンティックグラフ」「ノードグラフ」は上の関連付けの層、「エビングハウス複合記憶」は忘却曲線の層、「睡眠」は稼働していない時間にまとめて整理する工程に当たると考えられる（ポストに説明はなく本wikiの推測）。記憶のグラフを Obsidian と git という汎用のテキスト基盤に置く点は、llm-wiki が Markdown とリポジトリを知識の器にする選択と同じ土台に立っている。

忘却か再合成か

長期記憶を長く運用すると、断片化・矛盾・肥大で質が落ちる問題がある（2026-peng-llm-memory-faulty）。この設計は「忘却曲線で古い記憶を減衰させる」ことで肥大に対処する。一方 managed-agents-dreams のページでは、Anthropic の Dreams（重複削除・矛盾解消を非破壊で行い新しいストアを生成する公式機能）と、@AI_masaou が解釈した OpenAI の Dreaming（忘却曲線で消すのでなく裏で読み直して書き直す）が、ともに「消す」でなく再合成の方向だと整理されている。個人の自作システムが忘却曲線と睡眠工程を組み合わせているのは、両方を持つ設計にも見える。忘却で量を抑え、睡眠で整合を取り直す分担だとすれば、Dreams 型の再合成と対立するのでなく補い合う可能性がある（本wikiの推論）。

また、毎回の会話を要約して溜める工程は、2026-peng-llm-memory-faulty が指摘する「経験をコンパクトな教訓に繰り返し書き直すと記憶が劣化する」経路と重なる。要約は1回で止め、原文（Obsidian の日記や git 履歴）を残しておくかどうかが劣化耐性を分けると考えられる。

問い

  • 忘却曲線で減衰させる設計と Dreams 型の再合成は、1年運用したときどちらが劣化しにくいか。「睡眠」工程の中身（要約のやり直しか、リンクの再計算か）を @zapabob_ouj か @kuwagata_no_isi の一次情報で確かめる
  • 「無意識層」（常時稼働・命令なしで取得と関連付け）は自分の vault では何に当たるか。launchd の定期 ingest と lint は近いが、作業中の会話へ能動的に関連記憶を差し込む経路は持っていない
  • ベクトルDB・グラフの具体的な実装（ローカルか、どのDBか、埋め込みモデルは何か）は動画・実装ともに未収集
