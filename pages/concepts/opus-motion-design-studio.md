# Opus 5.5 モーションデザインスタジオ（seek(t) エンジン＋批評ループ）

> **TL;DR**: Opus 5.5 で「コードから描く動画」を量産するには、プロンプトより周辺の仕組み（決定論的な seek(t) レンダラ・リファレンス・状態リスト型の仕様・自分のフレームを見て直す批評ループ）が効く、と @0xMovez が12ステップの講座にまとめた。

> 📌 X bookmark: 20,396（2026-09-29 時点）

```mermaid
flowchart LR
  B["ディレクターズブリーフ<br/>（リファレンス・状態リスト）"] --> S["Opus が seek(t) を書く<br/>（index.html）"]
  S --> P["ヘッドレスブラウザ<br/>（Playwright）で全フレーム撮影"]
  P --> F["ffmpeg で MP4 化"]
  F --> C["Opus が静止画を採点<br/>最悪の3点を書き出す"]
  C -->|"全スコア 8 未満"| S
  C -->|"全スコア 8 以上"| D["納品（MP4・ポスター・コンタクトシート）"]
```

[[models/claude-opus-5-5]] の公開（@0xMovez によれば2026-09-22）直後、タイムラインはコードからレンダリングされたショーリール・ローンチ動画・音楽ビデオで埋まり、「ワンプロンプト」「モーションデザイナーは終わり」という反応が広がった。@0xMovez はどちらも半分だけ正しいとし、30語のプロンプトから出た作品がある一方で、9,500字のディレクターズブリーフ・スキルのフォルダ・APIキー2本・12時間の自律実行から出た作品もあると整理する。Claude Code チームの Thariq（[[concepts/effort-level-selection]] の @trq212）もこの落差を「投稿はワンショットと言うが、プロンプトはスキル・例・キー込みで1万字」と一言でまとめたという。講座の結論は「プロンプトは動画の10%で、残り90%はハーネス」で、[[concepts/harness-engineering]] の「エージェント = モデル + ハーネス」を動画制作に当てはめた実例として読める（推論）。

## Part 1: 何が起きているか

- **モデルは動画でなくプログラムを書く**: Opus 5.5 はテキストと画像を入力しテキストを出力するので、MP4 は出せない。この流行の動画はすべて、Opus が書いた `draw(t)` / `seek(t)` 関数（任意の時刻のフレームをそのまま描く純関数）を、ヘッドレスブラウザが 60fps・15秒なら900回呼んでスクリーンショットし、ffmpeg が結合したもの。タイマーに依存しないのでレンダリングは毎回同一になり、修正は1行の編集と再レンダリングで済む。
- **Opus の既定は依存ゼロの「ルートA」**: Tommy Rossi がワンショット出力を調べたところ、Opus は index.html 1枚・eval 経由で呼ぶ seek 関数・Playwright によるフレーム撮影・ffmpeg エンコードという構成を好み、[[tools/remotion]] や [[tools/hyperframes]] が使える環境でも選ばなかったという。フレームワークを使わせたいなら明示的に指定する必要がある、と @0xMovez は述べる。
- **セットアップは Claude Code 前提**: チャットアプリでもアニメーションは書けるが、レンダリングし・音を聞き・自分のフレームを見られるのはシェルを持つエージェント（[[tools/claude-code]] など）だけで、このフィードバックループが「微妙な初回」とバズった作品の差だとする。プロジェクト直下に CLAUDE.md の house rules を置けば毎回繰り返し指示しなくてよい。
- **effort**: @0xMovez によれば Opus 5.5 の既定は medium で、バズったワンショットはすべて xhigh か max で動いていた。小修正・再レンダリングは medium、新作は xhigh、冒頭3秒でローンチを背負うなら max を推奨する。

## Part 2: ディレクターとしてのプロンプト

- **ワンライナー**: 流行を作った9投稿のうち4本が「履歴書用の15秒ショーリール（showreel for a résumé）」「なんて凄いモーションデザイナーなんだ」「go all out」を含む同じ文を使った。@0xMovez の分解では、ショーリールというジャンルが「速いカット・1ショット1技法・最高作を先頭」という既知の規則を持ち込み、モデル自身を主題にすることで製品説明の誤りが起きず、15秒は1パスで終わり6〜8ショットが入る長さ、「go all out」は xhigh/max の上に乗る努力の乗数として働く。弱点は athemeroy のデータセットが「brief contagion」と呼ぶ現象で、同じプロンプトから互いに似たリールが大量に出た。「ワンライナーはエンジンを試すがアイデアは試さない。アイデアを含んでいないから」と @0xMovez は述べる。
- **ブランド向け**: Tony Dinh は1年前に1,000ドル超を払った類似のローンチ動画を30分未満で作った。追加したのは製品URL・「実際の製品スクリーンショット・ロゴ・素材を使う」・「音楽必須」の3行で、Opus がサイトから素材を自分で集めたという。Rob Hallam は同じチャットで続けて製品広告を頼むとレンダラ・音声合成・書き出しパイプラインが既にあるぶん速かったと報告しており、@0xMovez は「ブランドごとに1セッション」を勧める。achxvi は ElevenLabs キーを渡して製品を説明する喋るキャラクターを作り、声＋マスコットをサービスとして販売している。APIキーは .env に置き「ElevenLabs のキーは .env の ELEVENLABS_API_KEY」と書き、スクショする可能性のあるプロンプトに実キーを貼らない。
- **リファレンス**: リファレンスが無いと Opus は「中央寄せテキスト・グラデーション背景・全部フェードイン」の既定に戻る。Rexan Wong はバズった多数のクリップを調べ、スタイルは説明するより名指すほうが効き、参照動画・フレームがペース・書体・トランジションの手本になると結論づけた。参照の渡し方は、1フレーム（何を取り何を取らないかを添える）・動画（ffmpeg でフレーム抽出し、コードの前にショットごとのペースを記述させる）・自分のライブラリ（先に style_guide.md を書かせる）の3段。Pleometric が p5.js を提案したところ Opus は独自の紙質レンダラを書いたといい、@0xMovez は「見た目と制約を指定し、ライブラリは指定しない」ことを勧める。
- **状態リスト型の仕様**: 週で最もブックマークされたプロンプトはワンライナーでなく、@twoclipping の UI モーフ（907K再生・19Kブックマーク）と @verbove の MakerMap フィルムが使った XML 仕様だった。中身は「尋ねる入力・演出方針・ビートごとの状態リスト・ビルド規則・落とし穴」で、1つの形状がカットなしにボタン→ローダー→プレイヤー→スライダー→チャート→コマンドパレットとサイズ・角丸・色を変え、カーソルの実クリックが各変化を駆動し、最終フレームを最初のフレームと一致させてループさせる。NFT_Chen のエディタ映像は同じ発想を物語にしたもので、偽の UI は全要素の状態が既知の「セット」になる。

## Part 3: エンジンを作る

- **seek(t) レンダラ**: ルートAを2ファイル（任意の瞬間を描くページと、時間を進めてフレームを ffmpeg に流すレンダラ）で書き直す。フレームワーク派向けに同じプロンプトのルートBも示される（本文は画像で未捕捉）。
- **閉形式スプリング**: 安いモーションは固定カーブでAからBへイーズし、高いモーションは質量を持って加速し、わずかにオーバーシュートして落ち着く。モーフ系の作品が閉形式スプリング（時刻の純関数として書けるばね運動）を指定するのは seek(t) の決定性を保てるから。見落とされがちな点として、目標値が何度も変わる値（カーソル・コンテナ幅）はスプリングを再始動せず、変化ごとに開始時刻の違うスプリングを足し合わせる。こうすると動きが連続したまま、フレーム0〜811をシミュレーションせずにフレーム812を描ける。プリセットは Snappy（ボタン・トグル）・Default（カード・コンテナ・カメラ）・Heavy（大きな文字・3D・ロゴ）・Playful（マスコット・ステッカー、目に見えるオーバーシュート）の4種。
- **音をビートに合わせる**: @oozn のスティーブ・ジョブズ映像は Node でサウンドトラックを合成し全カットを 120BPM に固定、Vox の「small print」は Python で音楽を合成してから映像を1秒単位で磨いた。@0xMovez の方針は「曲を渡すなら計測し、渡さないなら映像と同じタイムラインで合成する」の二択。

## Part 4: 1本からスタジオへ

- **夜通し走らせるディレクターズブリーフ**: Donald は5分口述して寝ると、起きたとき142秒の音楽ビデオ（2.1M再生）ができていた。公開プロンプトは約9,500字、@pradeepXkapoor の「Pip」ロボット映像は19,000字で、どちらも「動画を記述せずクルーを雇う」骨格を持つと @0xMovez は述べる。項目は、1行のフィルム要約・リファレンス・ツールとキー（予算と「節約して使え」を含む）・キャラクターバイブル・タイムスタンプ付きビートシート（冒頭2秒にフック、3〜5秒ごとに見せ場）・画面上テキスト・ワークフローゲート（plan → rig → stills → animatic → full pass → polish → audio → render を飛ばさない）・批評ループ・納品物。Donald のブリーフの要は「generate-then-trace」で、Seedance 2.5 がキャラクターと物理の入ったベースショットを出し、Opus がその上から全編を JavaScript で描き直すので、視聴者はコードで描いた層だけを見る。John Heibel の PDoom リポジトリ（1.1K stars）では、Opus が並列実行するサブエージェント向けに ANIMATION_GUIDE.md を、初回生成後に STORYBOARD.md を書いており、@0xMovez は両ファイルを名指しで頼むよう勧める。
- **自分のフレームを見させる**: Opus 5.5 は画像を読めるので、レンダリングした静止画を採点し、最悪の3点を書き出して直し、全スコアが8以上になるまで繰り返せる。@0xMovez はこの習慣がバズった作品と「ちょっと微妙」と投稿された作品を分けたとする。@mablesjoseph の水彩短編は163回のモデル呼び出しと約7時間をかけたと明かしており、「反復は失敗でなく方法」の例として挙げられる。構造は [[concepts/eval-loop]] の「生成→採点→閾値未満なら戻す」を視覚出力に適用した形と考えられる（推論）。
- **出荷**: シーンを固定ピクセルでなくレイアウト関数に対して書き、9:16・1:1・16:9 を並列にレンダリングさせる（16:9 を縦に切り抜かない）。パイプラインをスキルに包めば講座全体が「/motion-reel for [URL], 20s, vertical, reference ./refs/frame.png」の1文に畳める。収益化の型として achxvi の提供内容（音楽・任意スタイルのマスコット・製品機能・最後にオファー・多言語・修正3回まで）と Tony Dinh の「1年前は約1,000ドル」という相場感が示される。

紹介されたリポジトリは PDoomVideo（音楽ビデオ）・ClaudeAnimationBase（スターター）・buildwithhanif/claude-animation-skill（Node canvas）・heygen-com/hyperframes（HTMLフレームワーク）・Remotion の AI スキル（Reactフレームワーク）・Battle-of-Austerlitz-Film（長尺）・guanmo-ai/awesome-ai-motion（プロンプト集）・athemeroy/awesome-opus-5-5-videos（データセット）。記事中の埋め込み投稿・テンプレート・コードの多くは画像や埋め込みで、本vaultには未捕捉。

## 問い

- 自分の環境で「seek(t) ＋ Playwright ＋ ffmpeg」のルートAと、[[tools/hyperframes]] / [[tools/remotion]] 経由のルートBを同じブリーフで回し、修正のしやすさと見た目の差を比べる
- 批評ループの「全スコア8以上」は同じモデルによる自己採点で、甘くなる余地がある。採点基準をブリーフ側に固定すれば足りるか、人の目のチェックポイントが要るか
- 「brief contagion」はスキル化して配布するほど強まるはず。スキル化とリファレンス（自分のライブラリ）の組み合わせで独自性を保てるか
