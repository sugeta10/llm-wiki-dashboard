# 後方互換を捨てさせる AGENTS.md 指示（開発中・社内向けPJ）

> 📌 X bookmark: 3,543（2026-10-03 時点）

コーディングエージェントは、既存コードを書き換えるときに古い呼び出し方を残す互換レイヤ・データ移行処理・念のためのフォールバックを足しがちで、開発中のプロジェクトではそれがそのまま負債として積み上がる。@sesere115 は「ここ1ヶ月ほど Codex で死ぬほど開発」した経験から、AGENTS.md（[[tools/openai-codex]] が入口として読む指示ファイル）に次の前提を書いておくと体験が「割と改善された」と述べる。

> 「これは社内向けサービスであり、開発中のPJのため後方互換やデータ移行は行わず、常に理想的かつKISSなコードに書き換えて下さい。開発は以下のサイクルで行って下さい」

この指示は3つの部品でできている（以下の分解は本 wiki の読み）。

- **前提の宣言**: 「社内向け」「開発中」と状況を先に伝える。外部利用者も本番データもまだ無いので、互換性を守る理由が無いことをエージェントに推論させる材料になる
- **禁止の明示**: 「後方互換やデータ移行は行わず」と、エージェントが善意で足しがちな作業を名指しで止める
- **到達点の指定**: 「常に理想的かつ KISS（Keep It Simple, Stupid＝できるだけ単純に保つ原則）なコードに書き換え」で、差分を最小にする方向でなく、あるべき形へ書き直す方向を既定にする

投稿は「以下のサイクルで行って下さい ↓」で終わっており、具体的な開発サイクルは本 vault には未捕捉（続きはスレッドか画像にあると考えられる）。

Anthropic の Fable 5 向けプロンプティング指針も「起こり得ないケースのエラーハンドリングやフォールバックを足すな」と同じ方向の制約を勧めている（[[concepts/fable-5-prompting]]）。モデル提供側と実践者の双方が、エージェントの「念のための保守的な追加」を指示で止める必要を感じている点は共通していると考えられる（推論）。

## 適用範囲

この指示が成り立つのは「外部利用者がいない」「捨ててよいデータしかない」という前提が真のあいだだけである。本番データや外部 API 利用者を持った時点で、データ移行と互換性はむしろ必須の作業になる。前提が崩れたときに AGENTS.md のこの行を外し忘れると、エージェントは既存データを壊す書き換えを正当な指示として実行しうる（推論）。

「理想的かつ KISS」の解釈も一意ではない。[[concepts/concept-design]] で takeshi_teshima は、KISS/YAGNI を「いま必要なコード量が最も少ない方」と読むと概念設計を誤ると指摘しており、書き換えのたびにエージェントが何を「理想」とみなすかは別途検証が要る。

## 問い

- 「開発中だから互換性不要」の前提を、いつ・誰が外すかをどう仕組みにするか（リリース判定と連動して AGENTS.md の該当行を消す、など）
- 毎回「理想形へ書き換え」させると差分が大きくなり、レビュー負荷が増えるのではないか。差分の大きさと負債の少なさのトレードオフを実測できるか
- 省略されている「開発サイクル」は何だったか。原ポストのスレッドを確認する
