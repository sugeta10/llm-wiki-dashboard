コーディングエージェント運用の2類型（高速制御 vs 委譲低速）

コーディングエージェントをヘビーに使って満足度が高い人は、両極の2つの型に分かれるという観察。中間（部分的に委譲しつつコードも掌握しようとする）よりも、どちらかの極に振り切ったほうが快適に回るという経験則。軸は「人間がコードをどれだけ掌握するか × ループの速さ」。

  • 高速制御ループ（Controlled fast loops）: 1〜2分の短いサイクルで、ほぼシングルスレッド。コードは人間が完全に掌握し、エージェントは「速くタイプする道具」として使う。レビュー負荷を増やさず、人間が常に流れの中にいる。
  • 委譲低速ループ（Delegated slow loops）: エージェントに任せて軽く誘導（nudge）しながら進める。人間はループの外に出て、量はエージェントが供給する。

委譲低速ループの極北が loop-engineering で、スケジューラー＋モデル＋フィードバックの三つ組で人間がループの外に出る。agentic-engineering-workflow の「人間は手をやめてシグナルになる」も委譲側に位置づく。一方の高速制御ループは、エージェントを並列構成する claude-code-orchestration とは逆に、シングルスレッドで掌握し続けるスタイル。この2類型は、どの運用スタックを選ぶかを「自分がどちらの極で快適か」から逆算する見取り図になる。

観察ログ（未検証）

  • 2026-06-20: @andy_matuschak が、コーディングエージェントをヘビーに使う友人のうち満足度が高い層は (a) 高速制御ループ と (b) 委譲低速ループ の「distant な2陣営」に分かれると観察。(b) の説明は元投稿のリンクで途切れており「Nudging along」までしか取得できていない（詳細未取得）。Notion の Simon Last（@simonlast）による「大規模プロジェクトでコーディングエージェントを運用して学んだこと。半年前のアドバイスの多くと矛盾する」という連投への返信として投稿された。

問い

  • 中間（部分委譲しつつ掌握）が本当に最も不満を生むのか。それとも単に2つの成功パターンが目立つだけで中間も成立するのか
  • 自分はどちらの極で快適か。タスクの性質（探索的か定型か）で使い分けるべきか
  • (b) 委譲低速ループの具体的な進め方（nudge の頻度・粒度）を、元スレッドや loop-engineering から補完したい
