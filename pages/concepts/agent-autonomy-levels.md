# エージェント自律度の4レベル

> **TL;DR**: エージェントかどうかは有無でなく4段の梯子であり、段を上げるのはモデルの乗り換えでなくツール・記憶・ループを1つずつ足すこと。

「この記事を要約して」はチャットであり、「このトピックで最も引用された論文3本を探し、各々の主要な主張を抜き出し、相互に突き合わせ、1ページのブリーフィングにまとめて」を途中で一度も手を触れずに走らせればエージェントになる。@Mahaximus_ はこの差を生むのはモデルではなくモデルの周囲の構造だとし、チャットが持たない3つを挙げる——自分の判断で呼べるツール、タスクを跨いで残る記憶、1回の応答でなく仕事が終わるまで回るループ。

```mermaid
flowchart LR
  L1["Level 1<br>チャット<br>人間がエンジン"] -->|"+ ツール"| L2["Level 2<br>ツール付き<br>答える前に自分で確かめる"]
  L2 -->|"+ ループ"| L3["Level 3<br>マルチステップ<br>ゴールを渡すと最後まで"]
  L3 -->|"+ トリガー / 記憶"| L4["Level 4<br>完全自律<br>起動も監視も人間なし"]
```

**Level 1（チャット）** は、聞いて答えてセッションが終わる状態。ツールも記憶も継続するゴールもなく、人間がエンジンでモデルは手の中の道具にすぎない。**Level 2（ツール付き）** は、答える前に検索する・ファイルを読む・自分の答えを確かめるためにコードを走らせる状態で、手順を指定していないのにモデルが必要だと判断してそうしている時点で、すでに部分的にエージェント的だと @Mahaximus_ は言う。**Level 3（マルチステップ）** はゴールを渡すとモデルが工程に分解し、各工程を実行し、結果を確認して完成物を返す状態で、工程の間に人間は入らない。**Level 4（完全自律）** はスケジュールやトリガーで起動し、入力を監視し、外部サービスを呼んで完了まで走る状態で、人間はゴールを一度設定して出力を確認するだけになる。

レベル1と4を隔てているのは別のモデルではなく、モデルを取り巻くもの——ツール・記憶・ループだと @Mahaximus_ は述べる。梯子として書く実用上の意味は、1段上げるのに必要なのが「もっと賢いモデル」でなく「足りていない1要素」だと特定できる点にある。

## 記憶が壊れる3つの形と、共通の1つの対策

エージェントが最もよく破綻するのは記憶で、しかも壊れ方は3通りある、と @Mahaximus_ は整理する。第一に、タスクが長引いて冒頭が落ちる——当初のゴール・すでに下した決定・課した制約がコンテキスト窓から溢れ、エージェントは働き続けながら何に向かっていたかを静かに忘れる。第二に、セッションを閉じて新しく開くとゼロから始まる。第三に、途中で中断されると、どこで止まったか・何を試したか・何が失敗したかの記録が残らない。

3つとも対策は同じで、**エージェント自身に自分の記憶を書かせる**。作業の途中で進捗記録を作らせる、セッションが長くなってきたら要約させる、新しいセッションの冒頭でそれを読ませて文脈を復元させる、という3つの差し込みで塞ぐ。加えて、定期的に走らせるエージェントについては、常に必要な事実をシステムプロンプトに直接書いておくことを @Mahaximus_ は勧める。システムプロンプトは毎セッションの冒頭で読まれるため、会話がどれだけ伸びてもそこにある情報だけは常にコンテキストに残るからだ。

## 上の2層との関係

@Mahaximus_ は agent・loop・graph を置き換えの列でなく積み上げとして提示する——エージェントはモデルに指示でなくゴールを渡して自力で進ませ、ループはその仕事を信頼できるものにし（自己採点し、失敗を記録し、基準を超えるまで続ける）、グラフは並列ワーカーで速くする。全部のタスクに3つとも要るわけではなく、目の前のタスクがどれを必要としているかを見分けられるようになった時点で、「もっと頑張る」から「もっとうまく設計する」へ移ると述べる。

ループ側について同記事が挙げる要点は、検査（check）が実際に失敗しうるものであること、停止条件を「完了」と「上限回数」の2本立てにすること、そして採算を「使った回数」でなく「実際に採用した出力の割合」で測ることの3点で、詳細は [[concepts/loop-engineering]] と [[concepts/loop-anatomy]] に厚い記述がある。グラフ側で挙げる要点は、順番と依存を混同しない（前の工程の出力を次が実際に読まないなら、その矢印は消せて並列化できる）、独立ジョブを並走させ最後に1つへ集約するダイヤモンド型、そして検査役には作業者と別の新鮮なコンテキストを与えることの3点で、こちらは [[concepts/graph-engineering]] と [[concepts/multi-agent-patterns]] が対応する。
