プロンプトキャッシュ事前ウォームアップ

Claude APIで time-to-first-token（初回トークン生成までの時間） を短縮するテクニック。システムプロンプトを実際のユーザーリクエストより先に送信してキャッシュに書き込んでおく手法。

仕組み

通常のフロー: 1. ユーザーリクエスト到着 2. APIへ（システムプロンプト + ユーザーメッセージ）を送信 3. キャッシュミス → システムプロンプトをキャッシュに書き込み 4. 推論実行 → 応答生成

事前ウォームアップ後のフロー: 1. アプリ起動時（またはシステムプロンプト変更時）にシステムプロンプトのみを事前送信 - この時点でClaudeはキャッシュへ書き込むが、出力は生成しない 2. ユーザーリクエスト到着 3. APIへ（システムプロンプト + ユーザーメッセージ）を送信 4. キャッシュヒット → システムプロンプト処理をスキップ 5. 推論実行 → 応答生成（高速）

実装ポイント

  • システムプロンプトのみを送信し、max_tokens=1 等で出力を最小化することでキャッシュ書き込みのみを実行できる
  • キャッシュの有効期限（TTL）を考慮してウォームアップのタイミングを設定する
  • 長いシステムプロンプト（ドキュメント、ツール定義、コンテキスト）ほど効果が大きい

効果が出やすいケース

  • システムプロンプトが長い（数千トークン以上）
  • 同一システムプロンプトで多数のリクエストを処理するサービス
  • レイテンシ要件が厳しいリアルタイムチャット・音声アプリ
