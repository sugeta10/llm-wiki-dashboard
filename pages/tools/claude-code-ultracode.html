Claude Code ultracode（総力戦モード）

TL;DR: プロンプトに「ultracode」と書くか/effort ultracodeを指定すると起動するclaude-codeのモード。推論を最深レベルへ切り替え、タスク専用のオーケストレーションプログラムを自動生成し、最大16並行・合計1000体上限のサブエージェント編成を組む（@ren_aivest解説、v2.1.203以降）。

1体のAIと会話する働き方から、数十体の編成を采配する働き方への切り替えだと@ren_aivestは位置づける。プレイヤーの道具ではなく監督業の道具、という言い回しがこの機能の性格をよく表している——ユーザーの画面に返るのは編成の作業が終わった後の最終結論だけで、途中経過はプログラム側に蓄積される。

使い方と裏側の処理

使い方は2つ。プロンプト本文に「ultracode」という語を含めるか、/effort ultracode を指定する。裏では次の3段階が起きる。

  1. 推論が最も深いレベルに切り替わる
  2. そのタスク専用のワークフロー（オーケストレーションプログラム）が自動生成される
  3. そのプログラムが最大16並行・合計1000体を上限とするサブエージェント編成を組む

/goal（完了条件を満たすまで自律的にターンを繰り返す機能、claude-code-goal参照）と組み合わせるときは1行に同居させるだけでよい。

/goal 記録アプリを公開する。全テスト通過とビルド成功とE2Eテスト通過。 ultracode

前半が検証込みの合格条件、末尾のultracodeが「この案件は編成を組んで総力戦でやれ」という体制の指定になる。合格条件で終わりを定義し、ultracodeで体制を定義する——1行の中に検収条件と戦力の指定が両方入る形だ。実際、316万インプレッションを集めた「Opus 5がFPSをワンショットで作った」という指示文（claude-code-goalに原文と分解を記録）も、/goal と ultracode を同じ1行に同居させたものだった。

効く場面と効かない場面

@ren_aivestは、網羅が要る仕事（全件レビュー・監査・移行）や作業を独立に並列化できる案件でultracodeが効くとする一方、会話で詰めたい相談ごとや小さな修正1件に使うのはコストに見合わないと述べる。普段は/goal単体で回し、総力戦に値する案件だけ末尾に一語足す、という使い分けを紹介している。この判断基準はclaude-code-dynamic-workflowsの「workflowは万能ではなくトークンを大幅に多く消費する」という注意点、graph-engineeringが紹介するAnthropic公式の「マルチエージェントは通常のチャット対話の約15倍のトークンを消費する」という数値とも整合する。
