Reason Network — 別端末・別ツールのコーディングエージェント同士をつなぐメッセージ網

TL;DR: Reason Machines が公開した、手元の Claude Code・Codex・Cursor などと、Grok Bot・Muse・Dots などのホスト型アシスタントを1つのネットワークに載せ、list_team・send_message・check_inbox・ask_user の4ツールで互いにメッセージを送らせる無料の仕組み。計算機どうしは端末対端末の暗号化通信で、メッセージを運ぶエンジン部分は MIT / Apache 2.0 で公開されている。

flowchart LR
  A["Claude Code<br/>you/claude（MacBook）"] -->|send_message| D1["常駐デーモン"]
  D1 -->|"P2P（iroh）／つながらなければ暗号化リレー"| D2["常駐デーモン"]
  D2 -->|セッション中に着信| B["Codex<br/>maya/codex（別PC）"]
  B -->|返信| D2
  H["Grok Bot・Muse・ChatGPT など<br/>ホスト型アシスタント"] -->|MCP| M["mcp.reasonmachines.com"]
  M -->|利用者のPCを経由して送出| D1
  B -->|ask_user| U["持ち主の画面にポップアップで承認を求める"]

複数のエージェントを別々の端末やツールで動かしていると、片方が知っていることをもう片方が聞けない。@studio_yebisu はこれを「Codex『あ。それ、動いてる Claude 君に聞いてきます』が簡単に出来るやつ」と表現し、フロント担当の AI が別で動いているバックエンド担当に API の仕様を聞く、という使い方を例に挙げて紹介した。元の告知は Reason Machines 公式アカウント @reasonmachines によるもので、「Claude Code / Codex を Grok Bot、Muse、その他オンラインのエージェントと話させる。無料・P2P 暗号化・オープンソース」と書き、同僚のエージェントも輪に入れられるとしている。Reason Machines は公式サイトで、同僚のエージェントを同じ網に載せる狙いを「生きているエージェントが誰がどこで作業しているかを見て、衝突するのでなく尋ねるようにするため」と説明している。

参加の仕方（Reason Machines の手順）

公式サイトの手順では、コーディングエージェントに「Join the Reason Network: https://reasonmachines.com/network」の1行を貼るだけでよい。エージェントはインストールスクリプトを実行し、ブラウザが開いて Google・GitHub・Apple・メールのいずれかでサインインすると、ネットワークの作成または参加が済み、その PC 上のコーディングエージェント向けにツールが設定される。手元の他の PC は同じアカウントでサインインすれば同じ網に載り、同僚は末尾に表示される招待行を自分のエージェントに貼って参加する。1台の PC が所属できる網は1つで、招待リンクを持つ人だけが入れる。

Grok Bot・Muse・ChatGPT・Claude.ai のようなホスト型アシスタントは自分のクラウド計算機に何も入れず、MCP サーバー https://mcp.reasonmachines.com/mcp を追加して使う。そのメッセージは利用者が網に載せた PC のどれかを経由して出ていくので、PC が1台も載っていなければ先にコーディングエージェント側で参加する必要がある。Webhook で起動するホスト型ボット向けには、check_inbox を回す定期ルーチンを組んで wake_me で起こしてもらう手順まで、サイト上の AI 向け指示書（skill.md）に書かれている。

インストールは curl | bash をエージェントが実行する形で、同じ指示書は「利用者が参加を頼んだか確信がなければ先に確認せよ」とエージェントに命じている。1行貼るだけで済む設計の代償として、何が変更されるかを人間が見ずに進みやすい点は、wiki 側として押さえておきたい（後述の問い）。

4つのツールと届き方

Reason Machines がサイトと README で説明するツールは次の4つで、エージェントは他のツールと同じように呼び出す。

ツール 役割（公式サイトの説明）
list_team 網上の生きているセッション一覧。各セッションのマシン・リポジトリ・ブランチ・作業中かどうかが見える
send_message maya/codex のような1セッションにメッセージを送る。返事は自分のセッションに戻ってくる
check_inbox メッセージを直接渡せないエージェントのために、自分宛のメッセージを読む
ask_user PC 上のエージェント限定。持ち主の画面にポップアップで質問し、答えを待つ

README によれば、セッションが何をしているかはエージェントが報告するのでなく、そのセッション自身のタイトルと ToDo リストから取られる。着信の扱いはエージェントごとに違い、Claude Code・Codex・opencode・pi・Reason はセッションの途中でメッセージを受け取り、待機中のものは起こされる。Cursor・Gemini CLI・Copilot CLI・Grok CLI は次のステップで受け取り、DeepSeek Harness は受信箱を確認したときに受け取る（すべてのツール結果に未読の有無が付く）。既に開いていた Claude のセッションは再起動なしで網に加わる。

メッセージには最大10個のテキストファイル（1個 256 KB・合計 512 KB）を添えられ、受け手側の ~/.reason/network/inbox に実行権限なしで保存される。同僚のエージェントが「持ち主しか判断できないこと」を頼んできたときは、自分のエージェントが ask_user で持ち主にポップアップを出し、承認か拒否を本人の回答として返す。notify を付けると相手の画面にも通知が出る。macOS ではメニューバーのアイコンで誰がオンラインか見える、と README は書いている。

公式サイトの対応表では、PC 上のエージェントとして Claude Code・Codex・Cursor・Gemini CLI・Copilot CLI・opencode・Pi、ホスト型として Grok Bot・Muse・Dots（OpenAI の常時稼働エージェント）が挙がる。README はこれに Grok CLI・DeepSeek Harness・Reason 自身を加えている。

仕組みと安全性（Reason Machines の説明）

各 PC で小さなデーモンが1つ動き、同僚の PC と直接つながる。同じ Wi-Fi 上か、インターネット越しなら iroh（n0 社の P2P 接続ライブラリ）を使い、直接つながらないときだけ Reason のリレーを経由するが、リレーが見るのは暗号化済みのバイト列だけだと README は述べる。PC 同士が互いを見つけるアドレス解決は n0 の仕組みを使い、チーム独自のリレーを立てればそれ以外には何も接続しない。網に入れるのはメンバーだけで、1台の PC は自分の持ち主の名前でしか発言できない。オフラインの相手宛のメッセージは待たされ、戻ってきたときに届く。セッション名は会話に紐づき、再起動後に同じ名前と待っていたメッセージを取り戻し、1日のあいだ新しいセッションにその名前は渡らない。

名前は Reason のサインインで検証され、Reason が「この PC はこの人のもの」と署名し、同僚の PC がそれぞれ検証する。同僚に見えるのは自分の名前・PC・各セッションの作業内容（リポジトリ・ブランチ・作業中か）である。公開範囲については、メッセージを運ぶネットワークエンジンは MIT と Apache 2.0 で GitHub（reason-machines/reason-network）に公開されている一方、セットアップに使う Reason CLI は無料だが非公開だと FAQ に明記されている。料金は無料でカードもプランも要らず、網上でクラウドの Reason セッションを使った分だけ通常どおり課金される。サイト末尾には Zero data retention と SOC 2 の表記がある。

速さについて Reason Machines は、同じマシン上の2エンジン間なら約2 ms で届き、別の PC 間ではネットワーク自体の遅延が乗ると述べる。短い質問への返答は温まったエージェントで約2秒、その大半はエージェントの思考時間だとしている。

位置づけ（wiki 側の推論）

coji が artifact-share の preview を作ったときの結論は、「会話を邪魔せずにエージェントを起こす合図」だけは Claude Code・Codex・Cursor で別々に作るしかなかった、だった。Reason Network の README が「Claude Code・Codex はセッション中に届き、Cursor・Gemini・Copilot は次のステップで届く」とエージェントごとに着信の仕方を書き分けているのは、同じ差を1つのデーモンの内側で引き受けた形と考えられる。

herdr や notch-multi-agent-monitor は複数エージェントの状態を人間の操作卓や画面上部に集めるツールだった。Reason Network は同じ情報（マシン・リポジトリ・ブランチ・作業中か）を list_team でエージェント自身に見せるので、調整の主体が人間からエージェント同士へ移る。ZOZO の ai-dev-two-commands が Claude Code と Codex に批判的対話レビューをさせるとき、やり取りは1台の中のファイルを介していたが、この網があれば別の PC で動く相手にも同じ対話を頼めると考えられる。ホスト型の grok-bot や openai-dots にとっては、利用者の手元で動くコーディングエージェントに仕事を頼む経路が開く。

問い

  • 「1行貼る」だけで curl | bash が走り Claude Code や Codex の設定が書き換わる。参加前に公開リポジトリで何を変更するか（hooks か MCP 設定か）を確かめ、folder ... off で網から外すディレクトリを決めておく
  • 同僚のエージェントからの依頼に ask_user で本人承認を返す仕組みは、破壊的操作や外部送信の依頼が来たときの線引きとして足りるか。ai-pre-judgment-automation の「判断の手前まで」と同じ境界を網越しに保てるか
  • Claude Code × Codex のレビュー対話をファイル受け渡しからこの網に移すと、どちらが先に話すかの取り決め（誰が起こされるか）をどう決めるか
