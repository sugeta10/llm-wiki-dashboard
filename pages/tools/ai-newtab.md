# AI Homepage（ai-newtab）

> **TL;DR**: 閲覧履歴から自分がよく読むサイトを選び、ログイン済みのブラウザで最大8ページを開いて、Claude Managed Agents のエージェントが毎回書き直す「新しいタブ」ページ。@trq212 が自作して毎日使っている Chrome 拡張で、自分の API キーで動かす。

```mermaid
flowchart LR
  H["getHistory: 閲覧履歴の上位ドメイン"] --> P["getPageHtml: 最大8ページを裏で開き整形"]
  P --> S["サンドボックスにファイルとして配置"]
  S --> G["grep / read: 見出し・投稿・リンクを抽出"]
  G --> W["write: React コンポーネント1つを生成"]
  W --> T["新しいタブで描画"]
```

@trq212 は、Max プランに月次の Claude API クレジットが付くという告知（[[business/claude-plan-api-credits]]）に添えて「自分のためのパーソナル AI をもっと作ろう」と書き、その例としてこの拡張を公開した。最初の投稿ではリポジトリが非公開のままで、後から公開したと本人が追記している。RSS や固定の情報源リストを持たず、ユーザーの実際の閲覧履歴を入力にする点が、情報源を人が選ぶ自動収集（[[concepts/ai-news-source-automation]]）との違いである。

## 仕組み

README の説明では、拡張のバックグラウンドワーカーが [[tools/claude-managed-agents]] のセッションをサーバーを挟まず直接動かす。`chrome.history` と `chrome.tabs` が必要な `getHistory`・`getPageHtml` の2つのカスタムツールだけを拡張側で実行し、それ以外はエージェントのサンドボックス内で処理する。取得したページは信頼できない入力として扱い、サンドボックスのシェルアクセスは切ってある。

- 検索エンジン・Web メール・銀行・ログアウト状態のマーケティングページは開く対象から外す。開けなかったページは隠さず報告する
- ページ上のリンクはすべてエージェントが実際に読んだページ由来で、URL を捏造しないよう指示している
- 設定の「Instructions」に書いた内容は毎回のビルドに入り、エージェントの既定より優先される。中身（「スポーツと政治は省く」）と見た目（朝刊風・1カラムの静かな読書リスト・GitHub 優先のダッシュボード・緑字の端末風）の両方をここで指定する
- モデルは Claude Sonnet 5.5（既定）・[[models/claude-haiku-5-5]]（最速・最安）・[[models/claude-opus-5-5]]（最も丁寧で最も高い）から選ぶ
- 自動再ビルドは既定でオンで、6・12・24・48時間の間隔を選ぶ。最初の1回を手動で作るまで始まらず、失敗したビルドは次の間隔まで再試行しない

## コストとプライバシー

1回のビルドが API キーに課金される1つのエージェントセッションで、費用はモデルと読む量で決まると README は説明する。拡張は閲覧履歴の要約（上位ドメイン・訪問回数・一部のページタイトル）と最大8ページ分の整形済み HTML を Anthropic API に送り、ページはログイン状態で読み込むため非公開の内容を含みうる。セッションとアップロードしたページはビルド終了ごとに削除され、API キーは拡張のローカルストレージに置かれる。作者は「初期の実験段階」と位置づけ、ブラウザプロファイルに触れられる人なら誰でも保存されたキーを読めるため、そのままストアに公開しないよう README に書いている。

## 問い

- Haiku 5.5 で24時間ごとに回した場合、月次 API クレジットのうちどれだけを消費するか。クレジット内で常用できる規模か
- 閲覧履歴を入力にすると、すでに読んでいるサイトの要約に閉じて新しい情報源に出会えない。このリポの X ブックマーク ingest と組み合わせ、「読んだもの」と「保存したもの」のどちらを起点にするかで出てくる面がどう変わるか
- ログイン状態で開いたページの内容がプロンプトインジェクションを含む場合、シェルを切ったサンドボックスと「読んだページのリンクだけ使う」指示で、生成されるページにどこまで影響が残るか
