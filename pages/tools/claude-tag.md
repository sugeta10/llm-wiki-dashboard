# Claude Tag（Slackでチームメイトとして働くClaude）

**Claude Tag** は [[companies/anthropic]] が発表した、チームがSlack上でClaudeをメンバーとして扱える機能（公式アカウント @claudeai が2026-06-23に発表）。Slackのワークスペースに人間のメンバーと同じようにClaudeを加え、選んだチャンネルとツールにだけアクセスを与えたうえで、メンションでタグ付けしてタスクを委任する。委任した側は別の作業に集中でき、Claudeはバックグラウンドで非同期に処理を進める。

> 📌 X bookmark: 10,104（2026-06-24 時点）

従来のClaudeは「人間が開いた画面で対話する相手」だったのに対し、Claude Tag は**Claudeを常駐するチームメンバーとして配置する**点が新しい。チャットボットを呼び出すのではなく、ワークフローが流れているチャンネルにClaudeが最初からいて、必要なときにタグ付けで仕事を渡す形になる。

## 仕組み

- **チャンネル単位のアクセス制御**: 管理者・利用者が「どのチャンネルに参加させるか」「どのツールを使わせるか」を選んで付与する。全社一律ではなく、見せたい範囲だけにClaudeを置ける。
- **タグ付けによる委任**: Slackのメンションと同じ操作でClaudeを呼び出し、その場の文脈（スレッドの会話・共有ファイル）を踏まえてタスクを任せる。
- **非同期の作業移譲**: 依頼者は応答を待ち続けず、Claudeが処理する間に別の仕事へ移れる。人に仕事を振るのと同じ感覚でAIに振る、という委任モデル。

Claudeが使う「ツール」へのアクセスは、外部サービスとの接続を担う [[tools/claude-mcp]]（Model Context Protocol）と同じ系譜にある。Claude Tag はその接続レイヤーを、Slackという既存のチームの場に持ち込んだ製品にあたる。

## 含意

- **AIを「相談先」から「同僚」へ**: タスクをチャットで毎回説明し直すのではなく、チャンネルの常駐メンバーに振るUXは、[[concepts/claude-code-task-delegation]] が扱う「人に仕事を委任するようにAIに委任する」という発想をチームコミュニケーションの場に適用したもの。
- **権限のスコープ設計が前提**: チャンネル・ツール単位でアクセスを絞れる設計は、組織でAIエージェントを運用するときの認可・ガバナンス（誰に何を見せるか）が製品レベルで織り込まれていることを示す。

## 問い
