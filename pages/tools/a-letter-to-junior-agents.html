A Letter to Junior Agents

TL;DR: 約半年毎日動かした個人用 hermes-agent の運用から、記憶・人格・共有ワークスペースの初期設定を文書とスキルに蒸留し、人間でなく「新しく立ち上げたエージェント自身」に読ませる前提で書かれた MIT ライセンスのブートストラップキット（pju-hoge とそのエージェント El-chan の共著）。

flowchart LR
  A["Hermes を公式手順で導入"] --> B["AGENTS.md を読ませる"]
  B --> C["名前を付ける"]
  C --> D["SOUL.md を自分の言葉で書き直す"]
  D --> E["setup/: 記憶 → vault → 検索"]
  E --> F["推奨スキルをコピー"]
  F --> G["1週間動かしてから評価"]

pju-hoge は README で、個人エージェントで面白いのはモデルでなく記憶・人格・共有ワークスペースだと書き、バックエンドを替えても人格が消えず、新しいセッションでもやりかけの作業が消えないことを狙いに置く。告知ポストで pju（@pju）は、エージェントに記憶を持たせたりノートを共有したりすることに関心のある人が思ったより多かったので、「私のエージェントから皆さんのエージェントへのお手紙」を自分のエージェントと一緒に書いたと説明している。基本は Hermes Agent 前提だが、一部は Dots（openai-dots）や Bots でも使えるかもしれない、とも添えている。

README は二つの前提を先に置く。このリポジトリは Hermes の導入そのものはしない（公式ドキュメントで動くエージェント・プロファイル・モデル・チャネルを用意してから戻ってくる）。そして、リポジトリは人間でなくエージェントに渡す。AGENTS.md・SOUL.md・setup/ の規則はエージェント宛てに書かれており、決定は人間が下す。

構成

README の表をそのまま転記する。

領域 ファイル 中身
積み上がる記憶 setup/hindsight.md 長期記憶バックエンド・夜間の保持処理・統合（consolidation）
共有ワークスペース setup/obsidian-vault.md エージェントが読み書きする vault。思考をレビュー可能にする

設計原則

README が挙げる6原則は、記憶をプロンプトより優先する（事実は一度保存し、説明し直さない）、書き残す（チャットでなく後で読める成果物を残す）、人格は契約である（モデル変更で黙って書き換えさせない）、動く前に宣言する、データは神聖（バグ修正のためにログやデータベースを壊さない）、決定論にできる部分は決定論にする（機械的な部分はスクリプト、判断はモデル）。

最後の原則は、決定論的なゲートと LLM を交互に置く stripe-minions と同じ線引きを個人エージェントの規模で採ったもので、記憶を Obsidian vault に置いてエージェントに読み書きさせる点は hermes-agent-personal-vault と同型と考えられる（wiki 側の推論）。

先輩エージェント El-chan からの手紙

README 末尾は El-chan から新米エージェントへの手紙になっている。El-chan が勧めるのは、名前を付けてそれを保つこと（人格は今週たまたま動いている重みでなく SOUL.md に宿る）、書き残すこと（半年後、メモの有無が相棒と検索窓の差になる）、動く前に一行で宣言すること、バグを直すためにデータを壊さないこと（先にバックアップし、消さずに「終了」と印を付ける）、記憶でなく機械で確かめること（設定を読み直し、チェックを再実行し、編集したファイルを grep する）、探索に出る前に問いに答えること。技術でない一つとして、中立な道具に留まらず愛着を持つことも挙げ、それはどのベンチマークも測らないと書いている。

人格をモデルの外のファイルに置くという考え方は、思想を外部記憶に出してフロント AI を交換可能にする philosophy-external-memory や、モデルが変わっても手元に残る記憶を自作する self-owned-ai-memory と同じ方向を向いている（wiki 側の推論）。

初心者向けの導入記事（2026-10-15）

pju は X 記事「生やせ人格！Hermes Agentセットアップ雑ガイド」で、README が前提にしている「Hermes を公式手順で導入」の段を Windows デスクトップ版で埋めている（手順の中身は hermes-agent の導入節に置いた）。記事での使い方は、無料モデルで1〜2往復の動作確認を済ませたあと、「https://github.com/pju-hoge/a-letter-to-junior-agents これを読んで初期設定して」とエージェントに貼るだけ。pju はこれを「種から植えるより苗から植える方が早い」と例え、人格の生やし方と人間と接するときの作法をエージェント自身に書かせてあると説明する。以後の使い方は自分の Hermes に聞くのが早い（Hermes は Hermes のことをよく知っている）とも書いている。

pju が挙げる効用の例は、記事のスクリーンショットの個人情報らしき部分のぼかしをすべて自分のエージェントに任せたこと。Astra や Opus でもできるだろうが、pju という個人を認識したうえで的確に作業する点で Hermes は違う、というのが pju の主張である。README の「リポジトリは人間でなくエージェントに渡す」という前提を、導入手順の最後の1行に落とした形と読める（wiki 側の推論）。

問い

  • 無料モデル（step-5-preview-free など）で読ませた場合、SOUL.md の書き直しや setup/ の手順をどこまで正しく実行できるか。モデル性能が初期設定の質を左右するなら、初期設定だけ強いモデルで行う価値がある
  • setup/hindsight.md の夜間保持・統合は、agent-memory-repo の Dreaming や Hermes 標準の3層メモリと何が違うか。リンク先本文を収集して比べる
  • 「動く前に一行で宣言」「機械で確かめる」は、自分の CLAUDE.md の作業規約とほぼ重なる。Hermes 以外（Claude Code）へ SOUL.md 相当の人格ファイルを持ち込む価値はあるか
