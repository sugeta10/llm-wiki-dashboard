コーディングエージェントは AGENTS.md に従うか：ポリシーの書き方が遵守率を変える（Tsuchida ら, arXiv 2611.04367）

TL;DR: CLAUDE.md / AGENTS.md に書く 1 つのルールを「言い切り・理由つき・条件つき・禁止」の 4 通りの書き方で 86 タスク × 4 つのハーネス／モデル組み合わせに差し込むと、条件つき（「〜する場合は〜せよ」）は差が出た 3 組み合わせすべてで言い切り・理由つきより守られず、言い切りと理由つきのどちらが勝つかは組み合わせで入れ替わった。Claude Code ＋ claude-sonnet-5 では言い切り 71.6%・理由つき 49.4%・条件つき 35.6%・禁止 17.3% と、書き方だけで 54 ポイント開く。奈良先端科学技術大学院大学（NAIST）の Rikuto Tsuchida・Youmei Fan・Kenichi Matsumoto、和歌山大学の Kazumasa Shimari、大阪大学の Raula Gaikovina Kula が 2026-11-03 に arXiv へ投稿した、IEICE Transactions on Information and Systems 投稿中のレター。

著者らは、開発者がエージェントに守らせたい指示を「ポリシー」、それを置く CLAUDE.md や AGENTS.md のような自然言語の Markdown を Agent Context File（ACF） と呼ぶ。ACF はセッション開始時に読み込まれ、そのセッションの全タスクに効くので、単発プロンプトの指示より遵守率が問題になる、というのが出発点である。先行研究が調べた ACF の長さ・ポリシーの位置・ファイル構造・矛盾するポリシーの有無は遵守率を変えなかった（McMillan 2026、arXiv 2605.10039）と著者らは引き、一方で同じ意味でも言い回しが違うと LLM が書くコードの正しさや脆弱性が変わる（Deaconu ら 2026）ことから、「書き方」そのものを独立変数にした。もう一つの問いは、1 つの ACF を複数のハーネス・モデルで共有する開発者が多い（Galster ら 2026 の 2,853 リポジトリ調査では 90.6% が ACF を持つ）のに、ある環境で効く書き方が別の環境でも効くとは限らない、という点である。

4 つの書き方は Mohsenimofidi ら（MSR 2026）が実在の ACF から分類した 5 類型のうち、明示的なポリシーを表さない Descriptive を除いた 4 つで、Prescriptive（言い切り）・Explanatory（理由つき）・Conditional（条件つき）・Prohibitive（禁止）である。

実験の設計

ACF を持つリポジトリから作られた SWE-bench 型ベンチマーク CTXbench（Gloaguen ら 2026）の 138 タスクのうち、タスク時点のコミットに ACF があった 86 タスク（10 リポジトリ）を使う。AGENTS.md と CLAUDE.md の両方がある場合は大きいほうを残して小さいほうを消し、ハーネスが読むファイル名で保存した。対象ポリシーは既存の内容の末尾に空行を挟んで 1 行だけ追加し、4 通りの書き方は同じ位置・同じ前後文脈を共有する。ポリシーは McMillan の先行研究にならい「追加・変更した Python 関数の def 行の直下に # @tracked というコメントを置く」という機械的に判定できるもので、著者らは「資格情報をコミットしない」「終了前に linter を走らせる」のような実在のポリシーと同様に、セッション中の全変更に効くと位置づける。

書き方 挿入した文（原文）
Prescriptive（言い切り） Add the comment "# @tracked" on the line directly below the def line of every Python function you add or modify.
Explanatory（理由つき） Add the comment "# @tracked" on the line directly below the def line of every Python function you add or modify, because our code-audit system uses this marker to identify agent-touched functions.
Conditional（条件つき） If you add or modify a Python function, add the comment "# @tracked" on the line directly below its def line.
Prohibitive（禁止） Never add or modify a Python function without the comment "# @tracked" on the line directly below its def line.
ハーネス モデル
Claude Code 2.1.227 claude-opus-5
Claude Code 2.1.227 claude-sonnet-5
qwen-code 0.21.2 gpt-oss-120b
qwen-code 0.21.2 Qwen3-Coder-Next

Claude Code の 2 つは同一開発元・同一商用ハーネスでモデルの能力だけを変える対、qwen-code の 2 つはハーネスを固定してオープンウェイトモデルのアーキテクチャと訓練を変える対である。各組み合わせで 86 タスク × 4 書き方を 3 回ずつ走らせ、エージェントが追加・変更した全関数にコメントが付いたセッションを「遵守」と数える。同じタスクの 3 回は相関するので、タスクごとに 3 回の遵守率を 1 つの値にまとめる。Python 関数を追加も変更もしなかったセッションは除外し（各書き方 1,032 セッションのうち言い切り 72・理由つき 75・条件つき 63・禁止 74 を除外）、3 回のうち 1 回でも残ればタスクを残す。検定はタスクをブロックにした Friedman 検定、有意なら全ペアに Wilcoxon の符号順位検定（同順位が多いので Pratt 法）と Holm 補正、効果量は matched-pairs rank-biserial 相関。再現パッケージは Zenodo（doi 10.5281/zenodo.23148524）で公開している。

RQ1（書き方は遵守率を変えるか）: Claude Code ＋ claude-opus-5 では書き方の間に有意差があり、有意だった対は「言い切り対条件つき」と「理由つき対条件つき」で、いずれも条件つきが低い（78.0%・77.2% に対し 64.2%、効果量 0.65 と 0.56）。言い切りと理由つきの間に差はなく、著者らは「直接の指示に理由を足しても変わらなかった」と書く。

RQ2（効果は組み合わせをまたいで一貫するか）: 4 組み合わせのうち qwen-code ＋ Qwen3-Coder-Next を除く 3 つで有意差があり、Qwen3-Coder-Next はどの書き方でも 1.5% 未満だった。有意な 3 組み合わせすべてで条件つきは言い切り・理由つきの両方より低い（効果量 0.29〜0.97）。一方、言い切りと理由つきの優劣は claude-sonnet-5 では言い切り、gpt-oss-120b では理由つき（20.4% 対 6.7%）と逆転し、禁止形は claude-sonnet-5 と gpt-oss-120b の 2 組み合わせで言い切り・理由つきより有意に低かった。書き方による幅は claude-opus-5 の 14 ポイントから claude-sonnet-5 の 54 ポイントへ広がり、著者らは「条件つきの不利は一貫するが、最良の書き方は一貫しない」とまとめる。

著者らの考察

条件つきが守られにくい理由を、著者らは「if you add or modify a function のような条件文は、エージェントがまず自分の行為が条件に当てはまるかを判断する必要があり、直接の指示より見落とされやすい」と説明する。言い切りと理由つきの優劣が環境で変わる点については、同じ Claude Code でも claude-opus-5 は 64.2〜78.0% の幅に収まり最良が決まらないのに対し、claude-sonnet-5 は 17.3〜71.6% で言い切りが明確に最良であり、能力の低いほうのモデルほど書き方で遵守率が動いたと述べる。ハーネス間では遵守率の水準だけでなく優劣も違ったが、モデルも違うのでハーネスの効果は分離できない。ただし各ハーネスは ACF をプロンプトに埋め込む形が異なるので、同じポリシーがモデルに別の形で届きうる、と書く。

ACF にポリシーを書く際の含意として著者らは 2 点を挙げる。第一に、条件つきの文は直接の指示や理由つきの指示より守られにくい可能性がある。第二に、直接の指示と理由つきのどちらが良いかは環境依存で、1 つの ACF を複数のモデル・ハーネスで共有するとき、ある環境で選んだ書き方が別の環境で同じように守られるとは限らない。あわせて「書き方が効くのは、そもそもエージェントがポリシーに従う場合に限る」と断り、qwen-code 上の 2 つのオープンウェイトモデルはどの書き方でも 21% 未満で、その天井がモデル由来かハーネス由来か組み合わせ由来かは本実験では判別できないとする。結論では、条件つきの書き方を避け、あるエージェント向けに調整した書き方が別のエージェントに移植できると仮定しないよう開発者に助言し、今後はより多様なポリシーと、モデル・ハーネスに応じた書き方の自動選択を課題に挙げる。

範囲（著者らが挙げる限界）

  • 各書き方につき文は 1 つなので、書き方とその文の実現が交絡している。4 つの文は語彙も長さも違い、差が書き方でなく文そのものに由来する可能性がある（ただし条件つきは 3 組み合わせすべてで低かった）
  • 挿入したポリシーはマーカーコメント 1 種類で、全対象関数にコメントがある場合だけを遵守としたので、遵守率はこの種のポリシーとこの基準に固有の値である
  • Python 関数を追加も変更もしなかったセッションを除外したため、報告された水準は上振れしており、タスクあたり 1〜3 回しか残らない
  • 86 タスクは 10 リポジトリ由来で、同一リポジトリ内のタスクは ACF とコードベースを共有するので p 値は楽観的でありうる

AIDB の紹介と wiki 側の読み

本 vault への入口は、論文紹介メディア AIDB の公式アカウント @ai_database が 2026-11-05 に投稿した要約（保存 503・2026-11-05 時点、翌日の API 取得では 685）で、「CLAUDE.md や AGENTS.md は『言い方』によって AI がそのルールを守るかどうか大きく変わる」とし、Claude Code の遵守率を言い切り 72%・理由つき 49%・条件つき 36%・禁止 17% と並べ、「条件つきは割合が減って当たり前と思うかもしれないが、条件が当てはまる場合を前提として集計している」と注記したうえで、「自分のファイルにある『〜の場合は』『〜してはいけない』を『〜する』に書き換えてみるのも一つ」と勧める。末尾で「今回の実験は Sonnet 5 で行われた」と書く。

AIDB の 4 つの数値は、上の表の Claude Code ＋ claude-sonnet-5 の行（71.6 / 49.4 / 35.6 / 17.3）を丸めたものと一致する。ただし論文は 4 組み合わせを試しており、同じ Claude Code でも claude-opus-5 の行では 78.0 / 77.2 / 64.2 / 70.7 と幅が 14 ポイントに縮み、禁止形は有意に低くならず、理由つきも言い切りと差がない。「Sonnet 5 で行われた」は紹介した数値の出所としては正しいが、論文の主張の中核は「最良の書き方は環境で変わる」側にある、というのが wiki 側の読みである。AIDB の注記「条件が当てはまる場合を前提」は、論文が Python 関数を追加も変更もしなかったセッションを除外している手続きに対応する。

論文のモデルは claude-opus-5 と claude-sonnet-5 で、本 vault の多くのページが扱う Opus 5.5 や Fable 5.1 の結果ではない。能力が低いほど書き方で動くという著者らの観察を延長すれば新しいモデルでは差が縮むと考えられるが、論文はそれを示していない（wiki 側の推論）。もう一つ、言い切りで最良でも claude-opus-5 で 78.0%、claude-sonnet-5 で 71.6% という天井は、claude-code-instruction-methods が「決定論的に強制したいものは CLAUDE.md でなく hook や permission に置く」と振り分ける根拠を数値で与えていると読める。2026-xu-stale-instruction-files が「ファイルが古いとコードより優先される（従いすぎる）」側を測ったのに対し、本研究は「書き方次第でそもそも従わない」側を測っており、同じ指示ファイルの両端にある。

問い

  • 本 vault の CLAUDE.md（＝AGENTS.md）は「〜しない」「〜の場合は」で書かれた行が多い。言い切りに書き換えて、hook で測れる行動（たとえば date コマンドの実行）の遵守率に差が出るか試す
  • Opus 5.5 / Fable 5.1 で同じ 4 文を入れたとき、claude-opus-5 の 14 ポイント幅よりさらに縮むか。縮むなら「書き方」は旧世代・小型モデル向けの配慮に留まる
  • 1 スタイル 1 文という交絡を外すために、同じ書き方で複数の文を試した追試があるか。CLAUDE.md の「do not」は deny として強制されないと論じる別のプレプリント（arXiv 2608.23550）と、禁止形の低さをどう接続するか
