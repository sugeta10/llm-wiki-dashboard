LLM Wiki 外部公開・活用促進 改善提案

作成日: 2026-05-30
対象: /Users/sugeta/environment/obsidian-vault の外部公開システム、ダッシュボード、wikiページ、ブックマーク活用ワークフロー

結論

このwikiの現在の問題は「モバイルで崩れるUI」だけではない。より大きい問題は、知識が ingest されたあと、ユーザーが明示的にクエリするまで価値が発火しないことにある。

改善の中心は、外部公開サイトを「保管庫の閲覧画面」から「知的好奇心を再点火するプロダクト」に変えること。具体的には以下の3本柱にする。

  1. モバイルファーストの閲覧体験: ダッシュボードとwikiページをPC/iphone両対応の情報設計に改修する。
  2. Weekly Insights Engine: 最近のブックマーク、既存wiki、孤立ページ、ホットクラスタを横断して、短い示唆・問い・次アクションを定期生成する。
  3. 知識品質の編集レイヤー: wikiページを単なる要約から「観察、関係、反証、次に試すこと」まで含む知識単位に引き上げる。

Opus 4.6案の評価と統合方針

wiki/outputs/2026-05-26-wiki-ux-improvement.md は採用価値が高い。特に、こちらの5/30案がプロダクト設計・PKMループを中心に捉えたのに対し、Opus 4.6案は実装箇所と工数順が具体的だった。

採用すべき点

| 項目 | 評価 | 統合方針 | |---| orphan: true ---|---| | @media(max-width:760px) が実質3規則のみという指摘 | 妥当 | モバイル改善の根拠として採用 | | cy.on('mouseover') がタッチデバイスで効かない | 重要 | グラフUX修正に追加 | | #kgraph 固定高さ・9pxラベル・100+ノード問題 | 重要 | モバイルでは折りたたみ/簡易表示を優先 | | Cytoscape同期ロード | 妥当 | ただしPhase 1ではなくバックログ寄り | | グラフヒント1行変更 | 高ROI | Phase 1 quick fixへ格上げ | | Stats Rowに「今週追加」を出す | 高ROI | ダッシュボード価値訴求として採用 | | Related Pages / 鮮度インジケーター | 高 | WikiページUX改善へ追加 | | Orphan Pages → Unconnected Seeds | 高 | すぐ実装する表現改善として採用 | | PKM 5軸スコア | 方向性は妥当 | 数値は仮説扱い。定性評価として採用 |

修正すべき点

  • Opus 4.6案は「今日2hでダッシュボード仮置き」まで踏み込んでいるが、現時点では実装前の提案統合フェーズなので、まずは優先度の再整理として扱う。
  • gen_weekly_insights.py を来週以降に置いている点は保守的で妥当。ただし手動Weeklyの反応が良ければ今週中に最小スクリプト化してよい。
  • Cytoscape遅延ロードは性能面では正しいが、最初に価値を変える施策ではない。モバイル折りたたみ後に必要性を再評価する。

統合後の判断

最重要は変わらず Weekly Insightsの静的プロトタイプ。ただし、並行して5〜30分でできるUI文言・CSS quick fixを先に入れるのがよい。理由は、Weekly Insightsを置いてもモバイルで読めなければ価値検証が濁るため。

改善提案

1. モバイル対応: ダッシュボードを「探索画面」から「二層UI」にする

現在の gen_dashboard.py は @media(max-width:760px) を持つが、実質的には bottom-grid を1列にする程度。Knowledge Graph、Recent Activity、Ranking、Categories、Most Referenced、Orphans が同列に近く、iphoneでは情報密度が高すぎる。

Opus 4.6案のコード観察により、追加で以下が問題として確度高く見えている。

  • #kgraph{height:356px} 固定で、スマホの縦画面ではグラフが画面を占有しすぎる
  • Cytoscapeノードの font-size:9 はスマホで読みにくい
  • cy.on('mouseover') ベースのツールチップはタッチ端末で機能しない
  • cy.on('tap','node',...) によるページ遷移は実装済みだが、「クリック/タップで開く」ヒントがない
  • ランキング行 grid-template-columns:28px 1fr auto は320px端末で詰まりやすい
  • タッチターゲットが44px基準を下回る箇所がある

提案する表示順:

  1. Weekly Insight / 今週の問い
  2. Hot Topics 3件
  3. Recent Activity 5件
  4. Bookmark Ranking 3件
  5. Graph / Categories / Orphans は折りたたみ

CSS/構造改善:

  • body に overflow-x:hidden
  • .dashboard paddingを clamp(12px, 4vw, 24px)
  • .dash-header をモバイルで縦積みまたは2列最小構成へ
  • .stats-row は横並びではなく2列カード
  • #kgraph はモバイルで高さ240px、またはデフォルト折りたたみ
  • .activity-item は grid-template-columns: 44px minmax(0,1fr)
  • .ranking-item は3カラムから rank + body の2カラムにし、bookmark数は本文下へ
  • 長いページIDは overflow-wrap:anywhere を使い、単一行省略だけに頼らない
  • タップ対象は最低44px相当の高さ
  • グラフヒントを「ホバーで繋がりを確認」から「タップでページを開く。PCではホバーで関連表示」へ変更
  • モバイルではCytoscapeを初期非表示にし、「Knowledge Graphを開く」ボタンで展開
  • Cytoscape遅延ロードは、折りたたみ実装後も初期表示が重い場合に実施

2. Wikiページ: 読む順番を設計する

個別ページはMarkdown本文をそのままHTML化しており、PCでは悪くないが、スマホでは「何を読めばいいか」の足場が少ない。

追加すべきページ部品:

  • TL;DR 3行
  • Why it matters
  • Related pages
  • Sources
  • Last updated / confidence
  • 鮮度インジケーター（例: updated 90+ days ago）
  • Next question

ページテンプレート案:

## TL;DR
- 何か
- なぜ重要か
- 何とつながるか

## 観察

## 既存wikiとの接続

## 未検証 / 限界

## 次に試すこと

## 関連

3. Weekly Insights Engineを追加する

ingest 後の活用不足には、定期的な編集出力が必要。これは「通知」ではなく「知識の再配信」である。

MVP:

  • scripts/gen_weekly_insights.py を追加
  • 入力:
  • 直近7日の wiki/log.jsonl
  • 直近7日の sources/twitter
  • 対象wikiページ
  • orphan pages
  • top referenced pages
  • 出力:
  • wiki/weekly/YYYY-WW.md
  • wiki/public-site/weekly/YYYY-WW.html
  • Slack/LINE用の短文

Weekly Insightの型:

# Weekly Insights: 2026-W22

## 今週の中心テーマ
AIエージェントは「チャットUI」から「実行環境」へ移っている。

## なぜそう見えるか
- Claude Code Dynamic Workflows
- OpenAI Secure MCP Tunnel
- Crabbox
- SaaS inside AI Agents

## 既存wikiとの接続
- [claude-code](../tools/claude-code.html)
- [openai-codex](../tools/openai-codex.html)
- [12-factor-agents](../concepts/12-factor-agents.html)
- [llm-wiki](../concepts/llm-wiki.html)

## sugeta-sanへの問い
自分の反復作業のうち、UIを触るより中間記法・skill・subagentに落とすべきものはどれか？

## 今週の小アクション
過去30日の作業から、1つだけ「skill化候補」を抽出して `sources/notes/` に保存する。

4. 通知は「新着」ではなく「問い」にする

Slack/LINE通知は新着一覧にするとすぐ読まれなくなる。通知は短く、問いと行動を含める。

通知例:

今週のLLM Wiki Insight

テーマ: AIエージェントは、SaaSの外側ではなく作業環境そのものになりつつある。

接続:
- Claude Code Dynamic Workflows
- OpenAI Secure MCP Tunnel
- SaaS inside AI Agents
- 中間記法パターン

問い:
sugeta-sanの反復作業で、GUI操作ではなくDSL/skill/subagentに落とせるものは何か？

次アクション:
今週1つだけ「自分用skill候補」をメモにする。

5. ダッシュボードを「状態表示」から「編集済みホーム」にする

現在のダッシュボードはページ数、リンク数、孤立ページ、グラフ、最近の更新を見せている。これはシステム状態としては有用だが、ユーザーへの価値訴求としては弱い。

新しいトップ構成:

  1. This Week's Insight: 編集された短いコラム
  2. Hot Clusters: 3つの関心クラスタ
  3. Continue Thinking: 関連ページ3件
  4. Recent Additions: 新着5件
  5. Knowledge Health: Orphansやリンク数は下部に移動

Stats Rowの変更:

現在の pages / categories / links / orphans は管理指標としては有用だが、「今週何が増えたか」が見えない。wiki/log.jsonl から直近7日のcreate/update数を集計し、次のように変える。

  • total pages
  • this week additions
  • links
  • unconnected seeds
  • updated date

6. 孤立ページを「欠陥」ではなく「未接続の種」として扱う

orphan_pages は現在警告に近い表現。だが個人wikiでは孤立ページは「まだ接続されていない新しい関心」の可能性がある。

改善案:

  • Orphan Pages → "Unconnected Seeds"
  • 各ページに「接続候補」を自動生成
  • Weekly Insightsで「今週接続すべき1ページ」を提示

7. 成功指標を変える

ページ数やリンク数ではなく、再利用と行動を測る。

North Star Metric:

週に1回以上、過去のwiki知識が新しい問い・判断・行動に接続された回数

計測イベント案:

  • weekly insight generated
  • weekly insight opened
  • related page clicked
  • action accepted / dismissed
  • source revived after 14+ days
  • orphan connected
  • query led to wiki update

セルフレビュー

妥当な点

  • ユーザーの問題意識は「モバイル崩れ」と「知識資産が使われない」の2層であり、UI修正だけでは解決しない。Weekly Insightsは後者に直接効く。
  • 直近データを見ると、すでにホットテーマのクラスタが明確に存在する。これは自動コラム化に向いている。
  • Slack/LINE通知は新着一覧ではなく、問いと次アクションにするべき。PKMの報酬設計として妥当。
  • ダッシュボードの現在の構造はシステム状態の可視化としては良いが、モバイルで最初に見る価値としては弱い。

弱い点 / 注意点

  • Weekly InsightsをLLM生成に頼りすぎると、もっともらしい一般論が増える危険がある。必ず wiki/log.jsonl と実ページへの根拠リンクを要求するべき。
  • 通知頻度を上げるとノイズ化する。最初は週1回、1投稿だけがよい。
  • LINE連携は実装コストや認証まわりがSlackより重い可能性がある。MVPはSlackまたはHTML公開ページで十分。
  • クリック計測は個人用途では過剰かもしれない。最初は生成物の質を手動で見ればよい。
  • モバイル対応はCSSだけで応急処置できるが、本質的には情報優先度の再設計が必要。
  • Opus 4.6案の実装指摘は有用だが、quick fixを積み上げるだけでは「知識が戻ってこない」問題は解けない。必ずWeekly Insightsとセットで進める必要がある。

反対意見への回答

反対: 「自分でクエリすればよいので通知はいらない」
回答: クエリは能動行動なので、忙しい週ほど発生しない。PKMの失敗は入力過剰・出力貧弱・報酬遅延で起きる。週1の短い問いは、報酬を前倒しするために必要。

反対: 「ダッシュボードは管理画面だから今のままでよい」
回答: 管理画面としてなら良いが、外部公開ページとしてユーザーが再訪するには弱い。PCでは管理情報、モバイルでは洞察を優先する二層UIにすれば両立できる。

反対: 「Weekly Insightsはニュースレターっぽくて大げさ」
