# AI時代のUXデザイン5メソッド

梶谷健人（POSTS代表/プロダクト戦略アドバイザー）がまとめた、AIでサービスを作る時代に必須のUX設計フレームワーク。「AIで作れること」と「求められるものを作れること」は別という問題意識から出発する。

関連: [[design/fastview-design]] | [[concepts/spec-driven-development]] | [[people/fladdict]]

## 1. UXの構成式

**UX = (u × e) / f** で捉える:

| 変数 | 意味 | 例 |
|------|------|-----|
| **u（便益）** | ユーザーが得る具体的利益 | レポート作成が30分短縮される |
| **e（情緒価値）** | 感情へのプラス影響 | 親しみやすいメッセージ・ビジュアルの洗練 |
| **f（フリクション）** | 障壁・困難の総和 | ステップ数・エラー率・認知負荷 |

**優先順位**: まずu最大化とf最小化 → その後eを磨く。「この画面はダサい」ではなく「fが大きい」「uが弱い」と分解して考えられるようになることが目的。

## 2. GarrettのUX 5レイヤー

下の層から順に詰めてからAIに実装させる:

| レイヤー | 問い |
|---------|------|
| **Strategy** | 誰のため？なぜ求められる？ |
| **Scope** | どの機能・コンテンツが必要か |
| **Structure** | 情報構造と画面遷移の流れ |
| **Skeleton** | 画面上の配置 |
| **Surface** | 見た目・感覚的側面 |

AIでサービスを作るほど、土台が固まらないまま実装に進みやすい。Strategyが曖昧なまま作ると「誰のためか」がぼやけ、Structureが雑なまま作ると導線がカオスになる。

**AIへの指示例:**
```
「UX5レイヤーのStrategyレイヤーの粒度で、このサービスのターゲットユーザーとゴールを整理して」
「Scopeレイヤーとして、機能要件や仕様を設計して」
```

レイヤーを分けてAIに指示すると出力クオリティが上がる（AIが「今どの粒度の話か」を明確に認識できるため）。

## 3. Information Architecture（IA）

GarrettのStructureレイヤーに相当。「情報をどう分類し、どんな導線でユーザーに届けるか」。飛ばされやすいが、機能が増えると後でツケを払う。

**User Flow** の設計が核心: ユーザーが目的達成までどの画面を通り、どのアクションをするかを図式化。現状フローを書き出すと「絡まり」（複雑・冗長な導線）が見つかる。

```
「Strategyレイヤーの内容を踏まえて、User FlowをMermaid記法で設計して。
  初期バージョンとフルバージョンの2パターンで」
```

## 4. Pre-Mortem（事前検視）

「このサービスが失敗した未来」を先に書き出す手法。自分たちのアイデアへの都合の良い見方を防ぐ。

```
「このサービス案が1年後に失敗したと仮定して、考えられる失敗理由を10個出して」
```

**重要**: 失敗理由を出して終わりにしない。「コア価値の体感が遅い」→「初回体験で擬似コア価値を体感させる工夫は？」と逆算して設計に組み込む。

AIはこのブレインストーミングの相手として相性が良い（人間が見落とすリスクを多角的に出せる）。

## 5. Problem Solution Fit（PSF）

**サービスアイデアの3要素**:
- 顧客（誰が困っているか）
- 課題（何に困っているか）
- 解決法（どう解決するか）

AIはこの3要素を整理するのは得意だが、「その課題で本当に困っている人がいるか」は知らない。**PSFは必ず人間が検証する**:
- ターゲットに10人インタビュー
- お金を払うか確認
- LPだけ作って反応を見る
- コア機能のみでクイックにリリース

AIで早く作れる時代だからこそ、「何を作るか」「何を検証するか」の判断力の重要性が増す。

## AI活用との対応

| メソッド | AIの役割 | 人間の役割 |
|---------|---------|---------|
| UX構成式 | 分析フレームの適用 | uとfの優先順位判断 |
| 5レイヤー | 各レイヤーの設計出力 | レイヤーを分けて指示 |
| IA/User Flow | Mermaid図の生成 | 「絡まり」の発見・解消 |
| Pre-Mortem | 失敗シナリオの列挙 | 設計への組み込み判断 |
| PSF | 仮説整理 | 現実の検証（必須） |
