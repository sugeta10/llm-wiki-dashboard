# Claudeを意思決定パートナーにするデザイン制作ワークフロー

> **TL;DR**: Claude（Team プラン）をデザイン制作の「作業自動化ツール」でなく意思決定パートナーとして使うワークフロー。HTMLでの自発的視覚化・Projectへのコンテキスト集約による一貫文書の連鎖生成・共有リンクとコメント→Send修正のコラボの3点が効く。

デザイン業務にClaudeを組み込むと、価値の中心が「速く作る」から「意思決定の質を上げる」へ移る。人間単独のプロジェクトでは、ユーザー理解（ペルソナ・カスタマージャーニー）に時間とコストがかかるため後回しになりがちだが、その制約が外れると下流のデザイン方針・機能検討・送客設計の各意思決定が良くなる。この転換を支えるのが次の3つの能力。

**HTMLによる視覚化**: ドキュメントをMarkdownでなくHTMLで生成させると、人間が「絵」として参照しやすく、AIにとっても構造を解釈しやすい。叩き台をチームに見せて共通認識を形成する速度が上がる。これはLLMにアプリフローをHTMLで渡すと精度が上がるという発見（[[concepts/llm-doc-management]]）の、デザイン制作側からの裏付けにあたる。

**コンテキスト集約＝チェイン・コンテキスティング**: 生成物をすべて同一Projectに蓄積すると、コンテキストが集約され、最小限の問いかけで一貫したストーリーの文書が連鎖的に生まれる。起点1ファイル（サービス構想資料）から、ペルソナ／ユースケース／カスタマージャーニーマップ → デザイン原則 → デザインシステム → プロトタイプ → 画面一覧・遷移図 → North Star Metric設計 → 送客設計、という流れを矛盾なく生成できる。指示を連鎖させる「チェイン・プロンプティング」に対し、文脈を連鎖させて整合した文書群を作るのが要点（[[concepts/claude-projects-blueprint]] のProject＝AI社員化の設計と同じ基盤を、制作フローとして使う形）。

**コラボレーション**: 生成物はURL1つで共有でき、権限は「閲覧のみ／コメント可能／編集可能／プライベート」の4段階。Team プラン保有者だけが閲覧できるためセキュアな社内共有に向く。コメントに付く「Send」ボタンを押すと、フィードバックがそのまま修正指示としてClaudeに渡りデザインが自動修正される。Figmaが担ってきたレビュー協業を、修正の実行までAIに接続した形になる。

- 「Send ボタンでフィードバックを修正指示に変換」はデザイン以外（wikiページのレビュー→修正）にも転用できるか。コメント→指示の自動接続を自分のワークフローに作れるか。
