# AIへ動きを名前で指示するための演出名リスト

@showheyohtaki が X で公開した、Claude や Codex に動きを頼むときのための演出名のまとめ。2026-10-08 に LP 向けの「よく使うおしゃれなアニメーション名」、2026-10-13 に動画向けの「モーショングラフィックスの演出名」を、いずれも動画と一覧画像つきで投稿した。

@showheyohtaki の主張は両投稿で共通している。「この辺をおしゃれに動かして」「カッコよく動かして」と形容詞で頼んでも狙った動きは出ず、演出の名前で頼めば思い通りの動きを実装・再現できる、というもの。名前は人間とモデルが共有している仕様の短縮形として働くと考えられる。形容詞はモデル側で無難な既定値へ落ちやすいのに対し、名前は特定の挙動（スクロール量との連動・要素の固定・減衰の仕方など）を一意に指す。

## 投稿が例に挙げた演出名

一覧の本体は画像と動画にあり、本ソースには投稿本文で例示された名前しか残っていない。以下はその転記のみ。

- **LP のアニメーション（2026-10-08）**: パララックス、スティッキー、スクロールスナップ
- **動画のモーショングラフィックス（2026-10-13）**: スタガー、オーバーシュート、マスクトランジション

用途で分けると、LP 側はスクロールに対するページの振る舞い、動画側は時間軸上の要素の出し方・止まり方・場面転換の名前である。動画をコードで描く場合（[[tools/remotion]] など）は、動画側の名前もそのまま実装用語として通じると考えられる。

## ライブラリ化: motion-prompt（2026-10-15）

@showheyohtaki はこれまで X に出してきた演出名を、動く見本つきのライブラリ「motion-prompt」（https://showheyohtaki.github.io/motion-prompt/ 、GitHub リポジトリ showheyohtaki/motion-prompt）にまとめた。投稿によれば、カメラワーク・UI パーツ・モーショングラフィックスなど5分野・120個の見本を収める（5分野の残り2つは本ソースに出てこない）。

使い方は、リポジトリを Claude Code や Codex に読ませて「motion-prompt のライブラリ出して」と頼む形。サイトの説明では、motion-prompt スキルを入れた AI がギャラリーをブラウザで開き、ユーザーは見本の「選ぶ」を押して複数選び、「冒頭のタイトルに」のような一言メモを添えられる。「AIに渡す」ボタン（AI がライブラリを開いたときだけ出る）で選んだ見本が AI に届き、そのあと「この動画の冒頭をこんな感じに編集して」と頼む。サイトはこれらを「見本」と位置づけ、同じような名前の見本を自分の分野・自分の言語で作るための手順とプロンプト（make-your-own）も公開している。

名前の一覧を読ませるだけの段階から、人間が動きを目で見て選び、選択結果を AI に構造化して返す段階に進んだと読める。形容詞を名前に置き換えるだけでなく、人間側が名前を知らなくても見本を指せば済むので、語彙を覚える負担を外したことになる（wiki 側の推論）。

## 問い

- 演出名を指定しても、モデルごと（Claude と Codex）・実装手段ごと（CSS・GSAP・Remotion）に解釈がずれる名前はどれか。名前に加えてパラメータ（イージング・時間・距離）まで渡すべき境界はどこか
- 一覧の本体（画像・動画）を取得して、名前と短い定義の対応表を自分用に持つ価値はあるか。[[design/design-md]] のような参照ファイルに入れて毎回読ませる形にできるか
- motion-prompt スキルの「AIに渡す」は、選択結果をどんな形式（名前だけか、実装コード片まで含むか）で AI に返しているか。リポジトリ本体を読んで確かめる
