# 「レイアウトに説明させる」（AI 生成 UI の説明過多を 1 行で抑えるプロンプト）

Agata（@agata。Pikku!・Biscuit・コピペ帳・日々のログ・ナノノートなどを作っているとプロフィールに記す個人開発者）が、GPT 系モデルの生成する UI に説明文が多すぎる問題への対処として、プロンプトに次の 1 行を足すことを勧めた投稿。

> 不要なセカンダリラベルや説明を避ける。レイアウトに説明させる

Agata によれば、これを付けるだけで「いい感じになった」。すでに説明が多くなっている既存の UI には、この 1 行に「UIリライトして」を足せばよいとも書いている。投稿本文はこの 3 行で、効き方の説明は添付した適用前と適用後の画面 2 枚に任せている。

## 適用前後（添付画像からの読み取り）

添付の 2 枚は、教科書の写真からふりがな付きの音読プリントを作るアプリ「よみより」の同じ画面の適用前と適用後。以下は wiki 側で画像を見て読み取った文言の差分で、投稿本文に説明はない。

| 要素 | 適用前 | 適用後 |
|---|---|---|
| 上部と見出し | 「おうちの音読サポート」のバー、「DAILY READING」のラベル、「きょうの「読めた」を、つくろう。」の見出しと「教科書の写真から、ふりがな付きの音読プリントを。」の副文 | 見出し「プリントをつくる」のみ |
| ステップ表示 | 「写真をとりこむ／本文・読みをたしかめる／プリントをつくる」 | 「取り込み／確認／印刷」 |
| 取り込みカード | 見出し「教科書をとりこむ」と副文「きょう読むところを、2ページまで。」、ドロップ領域に「写真を選ぶ、またはここにドロップ」「JPEG・PNG・WebP／2枚まで」とボタン、「スマートフォンで撮影する」、撮影のコツの注意書き、OpenAI API 設定の注意書き、送信と保存についての 2 行 | 見出し「教科書」、ドロップ領域に「写真を選ぶ」「2枚まで」、「撮影する」、送信についての 1 行。データの扱いは画面下の「▶ データについて」の折りたたみへ |
| 右カラム | 「こんなプリントができます」の見出し、見本、「見本でためしてみる」、印刷・赤シート・復習の 3 つの説明つき機能紹介 | 見本と「見本を使う」のみ |
| サイドバーと脚注 | ロゴ下のタグライン、「まいにちの音読」の節ラベル、スローガン 2 行と添え書き、装飾カード、脚注のスローガン | 3 つのメニュー項目のみ（「これまでのプリント」は「保存したプリント」に） |

差分から読み取れる操作は 3 つと考えられる。副文・注意書き・スローガンの削除、動詞句ラベルの名詞化（「写真をとりこむ」を「取り込み」に）、そして必要な説明の折りたたみへの退避である。指示が「説明を書くな」ではなく「レイアウトに説明させる」と代替手段を指定する形になっているため、情報を消すのではなく見出し・ステップ名・構造へ移す変換になっていると読める。

「いい感じにして」という形容詞でなく、やめること（セカンダリラベル・説明）と代わりの手段（レイアウト）を書く点は、[[design/ochiai-ai-design-method]] の「形容詞でなく設計変数で指示する」と同じ向きにある。画像生成で「AI 臭」を一言で消す [[design/chatgpt-image-anti-ai-look]] と同じ「一言足す」型を、UI に向けたものともいえる。参照仕様をプロジェクトに常駐させる [[design/design-md]] や、ダイヤル付きのスキルで没個性を防ぐ [[tools/taste-skill]] と比べると、本ページの対処は説明過多という 1 症状に絞った最も軽い手段と考えられる。

## 問い

- Agata は「GPT 特有」と書くが、Claude や Gemini が生成する UI にも同じ 1 行は効くか。説明過多がモデルの癖なのか、UI 生成プロンプト一般の癖なのかを切り分ける
- 適用後は撮影のコツや OpenAI 送信の注意が折りたたみに退避している。子ども向けアプリの初見ユーザーに必要な案内まで削れていないかを、どの基準で見分けるか
- この vault の HTML 出力や [[design/claude-premium-website-build]] のチェックリストに、この 1 行を常設の指示として足せるか
