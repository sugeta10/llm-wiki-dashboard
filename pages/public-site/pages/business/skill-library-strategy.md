# スキルライブラリこそ企業の最初のAI戦略

> **TL;DR**: 企業のAI優位はモデル選定でなく「自社の優れた仕事の進め方（判断）をスキルとして言語化・蓄積したライブラリ」から生まれる、というHiten Shahの戦略論。

多くの企業はAI導入を「アクセス」から始める —— CRM連携、Slack統合、Drive接続、データウェアハウス接続。アクセスは必要条件だが**良い仕事を生まない**。エージェントは全ての営業メモを読んでも商談の「形」を見落とし、全サポートチケットを検索しても今すぐ対応すべき顧客を認識できない。本質的な課題は「エージェントのアクセスを広げること」でなく「自社がその仕事にどう取り組むかをエージェントに理解させること」にある。そこを埋めるのがスキルである。

**スキルはプロンプトでなく「再利用可能な仕事の進め方」**。プロンプトが特定の瞬間の指示なのに対し、スキルは繰り返し可能な手順・判断・エッジケース・品質基準をパッケージ化し、同種のタスクが来るたびに同じアプローチを適用させる。Anthropic版は `SKILL.md` を含むフォルダ構造（[[concepts/claude-skills]]）。営業準備なら「アカウント履歴の読み方・浮かべるべきリスク・良いブリーフの形」、インシデントのポストモーテムなら「タイムライン再構成・原因と症状の分離・非難なしの記述」といった**手練れが暗黙にやっていること**を明文化する。

技術史の系譜として位置づけられる:

| 抽象化 | 再利用したもの |
|--------|--------------|
| Unixコマンド | 有用な操作 |
| シェルスクリプト | 操作のシーケンス |
| ライブラリ | コード |
| API | サービス |
| ワークフロー | 業務プロセス |
| **スキル** | **判断（judgment）** |

変わったのは「実行者」である。これまで人間がプレイブックを読んで適用していたが、今やエージェントがプレイブックをロードし、ツールを使い、ファイルを検査し、スクリプトを走らせて進められる。**プレイブックがアクティブになった**ことが、仕事の進め方を文書化する価値を一変させた。

進化の段取りは「データ／コネクタ（MCP・API・[[tools/claude-mcp]]）→ スキル → 両者を束ねるプラグイン」。コネクタはSalesforceを露出できてもフォーキャストレビューの回し方は教えられない。**データ＝文脈、スキル＝判断・手順**という役割分担。

戦略的含意:

- **スキルライブラリが資産になる**: 同じフロンティアモデルを使う2社でも、片方が「自社最良の仕事から作ったスキル群」を持てば別物の資産になる。良いスキルは同じミスの二度の修正を防ぎ、優れたスキルは全員の床（floor）を上げ、最高のスキルは習得に何年もかかった判断を捉える。
- **最良のスキルは私有（private）になる**: 公開マーケットプレイスのスキルは大半が汎用。本当に価値あるメソッド（顧客エスカレーション基準・営業の見極めレンズ・取締役会向けの語り口・法務のフォールバック・ブランドの声）は具体的ゆえ社内に留まり、競合がダウンロードできない知識になる。
- **仕事から始める**: プラットフォーム選定の前に繰り返し仕事をマップし、経験者が一貫して周囲を上回るワークフローを探す。「その人は何にまず注目し、何を見落としがちで、どの例が判断を形作っているか」を聞き出し、それを素材にスキル化→運用→改善し、オーナーを仕事の近くに置き続ける。

結論は「AIを業務に薄く振りかけるのをやめ、トップパフォーマーの繰り返し判断を再利用可能なシステムに変えて深く埋め込め」。企業のAI優位は選ぶモデルでなく、モデルに上手くやらせるよう教えた仕事から来る。
