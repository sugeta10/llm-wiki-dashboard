# Claude Managed Agents

[[companies/anthropic]] が提供するエージェント管理プラットフォーム。長期実行エージェントのメモリ管理・自己改善・マルチエージェント協調を提供する。

## 主要機能

### Dreaming（自己改善型メモリ）

スケジュール実行されるプロセスで、過去のエージェントセッションを振り返り、パターンを抽出してメモリを再構成する。

- 複数エージェント間で共有された学習内容を統合
- 個々のエージェントが見逃すパターンを横断的に発見
- 自動更新 or レビュー後更新の2モードを選択可能
- Harvey（法律文書生成）での実績：完了率 約6倍向上

### Outcomes（評価ループ）

成功基準をルーブリック（採点基準）として定義し、別コンテキストの評価エージェントが採点してフィードバックループを形成する。

- エージェントの推論バイアスを排除した独立評価
- 標準プロンプトループ比で最大 **+10ポイント** のタスク成功率向上、難問ほど効果大
- docx生成 **+8.4%**、pptx生成 **+10.1%** のファイル生成品質向上（内部ベンチマーク）
- Wisedocs での実績：レビュー速度 50% 向上
- Webhook 通知との組み合わせで非同期ジョブ型実行が可能

### Multiagent Orchestration（マルチエージェント協調）

リードエージェントがタスクを分割し、専門エージェントに委譲する設計。

- 各サブエージェントが独自のモデル・プロンプト・ツールを持つ
- 共有ファイルシステムで並列作業
- イベントが永続化されるため、エージェント間での状態共有が可能
- Claude Console で全エージェントの行動をトレース可能

活用事例：
- **Netflix**: 数百ビルドのログを並列分析し、複数ビルドにまたがるパターンのみを抽出
- **Spiral by Every**: Haiku がオーケストレーターとして受付・フォローアップを担当し、複数ドラフトは Opus サブエージェントが並列生成。Outcomes でブランドボイス評価ルーブリックをメモリから参照しスコアリング

### Webhooks

エージェントの完了通知を任意のエンドポイントに送信。非同期ワークフローとの統合が容易。

## Memory + Dreaming の組み合わせ

- **Memory**: 各エージェントが実行中に学習した内容をリアルタイムにキャプチャ
- **Dreaming**: セッション間でメモリを精製、エージェント横断で共有知識を統合

→ 長期稼働・マルチエージェント環境での「組織的学習」を実現する。

## 料金体系

「トークン料金 ＋ 稼働時間料金」の2軸。

- トークン料金: 通常の Messages API と同じ（Opus 4.7: 入力$5/出力$25 per 1M）
- 稼働時間料金: **$0.08 / session-hour**（待機中は課金なし）

| モデル | 1時間あたりの概算コスト |
|-------|----------------------|
| Opus 4.7 | 約$0.71 |
| Sonnet 4.6 | 約$0.46 |
| Haiku 4.5 | さらに安価 |

ビジネスモデル上の意義: Anthropicが「質問1回ごとに課金するモデル」から「エージェントの稼働時間を売るモデル」へ転換。

## セキュリティ機能（2026-05-19 追加）

@ClaudeDevs（公式）が発表した2つのセキュリティ改善：

### Self-hosted Sandboxes
エージェントの実行環境を **自社インフラ** または **マネージドサンドボックスプロバイダー** に置ける。Anthropicのクラウドを通さずに実行でき、データが自社セキュリティ境界内に留まる。

### MCP Tunnels
エージェントがセキュリティ境界内のサービス（社内システム・DB等）に接続できるトンネル。[[tools/claude-mcp]] ベースで、ファイアウォールを越えずに内部リソースに安全にアクセス。

→ エンタープライズの「データを外に出したくない」という要件に直接応える機能。[[concepts/claude-code-security]] と組み合わせることで、エンプラ向けClaude展開の完全なセキュリティスタックが構成できる。

## 新機能（2026-06-11 追加）

@ClaudeDevs（公式）が発表した2つの機能追加：

### Scheduled Deployments（スケジュール実行）

タスクをスケジュールに従って自動実行する機能。エージェントを定期的に起動し、夜間バグトリアージ・週次レポート生成・日次データ処理などの反復ジョブを無人で回せる（Routines 機能の正式展開）。[[concepts/loop-engineering]] のオートメーション要素に対応する。

### Environment Variables（環境変数）

Vault に保存した認証情報をCLI向けに環境変数として公開する機能。エージェントが外部CLIやAPIにアクセスする際の認証情報を安全に注入できる。

## 公式仕様（2026-05-23 公式ドキュメントより）

### コアコンセプト

| 概念 | 説明 |
|------|------|
| **Agent** | モデル・システムプロンプト・ツール・MCPサーバー・スキルの定義セット |
| **Environment** | セッション実行環境の設定（Anthropicマネージドクラウドコンテナ or 自社ホスト） |
| **Session** | 特定タスクを実行しアウトプットを生成するエージェントの実行インスタンス |
| **Events** | アプリケーション↔エージェント間のメッセージ（ユーザーターン・ツール結果・ステータス更新） |

### 組み込みツール

- **Bash**: コンテナ内シェルコマンド実行
- **File operations**: Read / Write / Edit / Glob / Grep
- **Web search and fetch**: Web検索・URL取得
- **MCP servers**: 外部ツールプロバイダーとの接続（[[tools/claude-mcp]]）

### レートリミット（組織単位）

| エンドポイント種別 | 上限 |
|---------|------|
| 作成系（agents・sessions・environmentsなど） | 300 req/min |
| 読み取り系（retrieve・list・streamなど） | 600 req/min |

### データ保持・コンプライアンス注意事項

- Managed Agents は**ゼロデータリテンション（ZDR）対象外**・**HIPAA BAA対象外**
- セッション・ファイルはAPIから随時削除可能（ユーザー主導）

## エージェントシステムプロンプト設計フレームワーク

信頼性の高いエージェントのシステムプロンプトに含める4要素:

1. **役割の明示**: 汎用「helpful assistant」でなく具体的な職能を与える（例: 「競合インテリジェンス専門のリサーチアナリスト」）
2. **成功基準の定義**: 期待するアウトプットの形式・分量・必須の構成要素を明示（例: 「各競合について変更点をカテゴリ別にリストし、推奨セクションを末尾に付ける」）
3. **禁止事項の明示**: 「データを捏造しない・確認できない情報はflagする」等のバウンダリ
4. **エッジケース対応**: 「サイトがダウンしている場合はログに残して継続し、最終レポートに不完全性を明記。リトライは最大2回」等

曖昧なプロンプト → 曖昧なエージェント。精密なプロンプト → 信頼性の高いエージェント。

## よくある失敗と対策

| 症状 | 根本原因 | 対策 |
|------|---------|------|
| 指示されていないことをやる（やりすぎ） | プロンプトが曖昧 | 「上記のステップのみ実行する」等の明示的制約を追加 |
| 表面的な出力しか出ない（やらなすぎ） | 「完了」の定義が不明確 | 期待する成果物の具体例・量・フォーマットを明示 |
| ハルシネーション | 検証ステップなし | 「データポイントを含める前にソース素材で確認する。確認できなければ除外し不足を明記」 |
| エッジケースでクラッシュ | エラー処理未定義 | 「〔特定シナリオ〕の場合は〔具体的行動〕」をプロンプトに追加 |

→ 最初のエージェントが1度で完璧に動くことは稀。5〜10回のイテレーションでプロンプトを精錬するほど出力品質が上がる。
