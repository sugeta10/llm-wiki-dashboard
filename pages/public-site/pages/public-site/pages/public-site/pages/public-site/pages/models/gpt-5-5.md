# GPT-5.5

OpenAIの大規模言語モデル（2026年）。アウトカム重視のプロンプト設計が推奨されており、過剰な手順指定よりも「良い結果の定義」を渡す方が効果的。

## プロンプト設計のパラダイムシフト

旧来モデルとの最大の違い：

- **旧**: 手順を細かく指定（「まずAを確認し、次にBと比較し、次にすべての例外を検討し…」）
- **新**: 目的・成功条件・制約を渡す（「問題を解決せよ。成功条件はX、制約はY、利用可能情報はZ」）

旧プロンプトをそのまま使い回すと「指定過剰」でモデルの探索空間を狭め、機械的な回答を招く。GPT-5.5に移行する際は旧プロンプトの手順指定を整理することが推奨。

## 推奨プロンプトパターン

### アウトカムファースト ＋ 停止条件

目的と成功条件を定義し、停止条件を明示することでループ効率が上がる：

```
顧客の問題をエンドツーエンドで解決せよ。
成功条件:
- 利用可能なポリシーとアカウントデータから適格性判断が完了
- 許可されたアクションはすべて回答前に実行済み
- 最終回答にcompleted_actions / customer_message / blockersが含まれる
```

### 検索バジェット（Retrieval Budget）

RAGシステムでの検索回数を明示的に制御する停止ルール：

> 「最小限の証拠で正確に答え、正確に引用し、停止する」

追加検索が許可されるのは「回答に必要な事実が欠けている場合のみ」。文言改善・例示追加のための再検索は不要。

### ペルソナとコラボレーションスタイルの分離

- **Personality**: トーン・親しみやすさ・直接性（ブランドボイスの定義）
- **Collaboration style**: いつ質問するか、前提を置くタイミング、積極度（タスク挙動の定義）

2つは別のインストラクションブロックで短く定義する。

## Codexによる自動移行

```
$openai-docs migrate this project to gpt-5.5
```

Codexがこのガイドに基づき旧プロンプトをGPT-5.5向けに自動移行。OpenAI skills repositoryから他エージェントでも利用可能。
