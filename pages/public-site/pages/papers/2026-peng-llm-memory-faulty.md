# LLMメモリの継続更新による劣化

> **TL;DR**: LLMエージェントが過去の経験を「コンパクトな教訓」に繰り返し書き直してメモリを継続更新すると、メモリは改善されるどころか劣化（faulty）し、有用だった経験が壊れやすくなる。

## 概念説明

LLMエージェントは、過去の経験を毎回フルに保持する代わりに、テキストの「教訓（lessons）」や要約に圧縮して再利用可能なメモリへ変換することが多い。このメモリ統合（memory consolidation）を継続的・強制的に繰り返すと、情報が累積的に書き換えられていく。

問題は、この書き直しが単調に品質を上げないことにある。経験を繰り返しテキスト教訓に再要約すると、当初は有用だったメモリが劣化し、壊れやすく（fragile）なる。各更新ステップで微妙なニュアンスや前提が失われ、誤りが累積する方向に働きうるため、結果として下流タスクの性能が更新前より悪化することがある。

設計上の含意は、メモリ更新を「常に良くなる操作」と仮定してはならないこと。継続更新には品質劣化のトレードオフがあり、何を統合し何を生データのまま残すか、いつ更新を止めるかを明示的に管理する必要がある。[[concepts/self-refining-skills]] のような自己改善ループ（LESSONS.md方式）や、[[tools/hermes-agent]] のように外部の最適化パイプライン（オフライン最適化）でメモリ品質を担保する設計は、この劣化問題への対処として位置づけられる。

## 観察ログ（未検証）

- 2026-05-16: 複数の環境で、強制的なメモリ統合（forced consolidation）が有用な経験を劣化させるパターンが繰り返し観察されたと著者が報告
- 2026-05-16: 継続的に統合されたメモリは「壊れやすい（fragile）」傾向があり、期待に反して悪化しうる、という著者の主張
- 2026-05-16: 関連コメント（@dylan_works_）: 「LLMエージェントが経験を繰り返しテキストの"教訓"に書き直すと、メモリが良くなるのではなく悪くなる」
